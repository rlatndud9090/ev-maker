# ADR: 파티 6칸과 PokePaste 가져오기

> 작성 고도: ADR은 "어떤 구조를 왜 골랐나"의 근거 저널이다. 코드 스니펫·전체 설계문서를 본문에
> 넣지 않는다(과대 ADR) — 상세 구현은 코드·별도 설계문서로 내린다. 사람은 중립 역할어로만
> 지칭하고 개인 호칭·별명은 넣지 않는다. 참고: `harness/templates/examples/README.md`.

## 컨텍스트

- **PRD 요구**
  - 파티 6칸, 칸마다 세트·기술 선택·컷 고정·기준 갈래를 따로 유지하고 칸 전환으로 고정이 풀리지 않는다(R5·R7).
  - 상대 쪽 사용자 추가분(커스텀 상대·추가 배분·핀 배분·스피드 추가)과 화면 설정은 파티 공통(R11·R13). 커스텀 상대 삭제 시 모든 칸의 해당 고정을 함께 푼다(R12).
  - PokePaste 링크로 6칸을 통째 교체, 레귤레이션에 없는 항목은 그 항목만 비우고 보고(R14~R21).
  - 파티와 전역 목록을 브라우저에 저장·복원, 깨진 데이터는 버리고 기본 상태(R22~R24, N4).
  - 기본 상태(한 마리)에서 세 탭 결과는 지금과 같다(N6, 불변식 INV-261120-no-lock-identity와 같은 방향).
- **현재 코드/데이터 제약**(2026-11-20 조사, notes)
  - 앱 상태는 리듀서 하나에 세트 하나다. 세트 필드(`draft`, `draftCache`), 컷 고정 필드 묶음, 기술 선택, 세대 카운터가 세트에 딸려 있고, 나머지는 화면 전역이다.
  - 종 변경 액션은 기본 종이 다르면 고정을 모두 푼다. 칸 전환이 이 경로를 타면 R7이 깨진다.
  - 저장 계층이 전혀 없다(모두 메모리).
  - 세트 초안은 종·도구·기술을 한국어 표시 라벨로, 특성·성격을 id로 든다. 이름 색인은 소문자 영어 이름·id·한국어 라벨을 모두 받는다. 메가는 (기본 종, 폼, 스톤) 표로 고르고 스톤은 일반 도구 선택에서 빠진다.
  - 고정 대상 키는 상대를 (출처, 상대 id)로 가리킨다(G-261119-added-bundle-source-compare).
- **사용자 경험 제약**: 헤더 배치는 사용자가 직접 지정했다(왼쪽 정사각형 6칸 + 오른쪽 링크 입력·가져오기). 확인 단계는 파티 교체·파티 비우기 두 곳.
- **검증 제약**: paste 해석은 네트워크 없이 고정 표본으로 단위 테스트(N5). 기존 봉인 fixture는 갱신하지 않는다.

## 결정

### 결정 1. 칸 상태는 "활성 칸은 지금 자리, 나머지는 보관함"으로 교체한다

기존 상태의 세트 딸림 필드(이하 칸 조각)를 한 목록으로 정의하고, 활성 칸의 조각은 지금처럼 상태 최상위 필드에 그대로 둔다. 비활성 칸의 조각은 파티 보관함(6칸 배열, 빈 칸은 없음 표시)에 넣어 둔다. 칸 전환은 "현재 최상위 조각을 보관함의 활성 자리로 내리고, 대상 칸 조각을 최상위로 올리는" 한 액션이다. 종 변경 액션을 거치지 않으므로 고정이 풀리지 않는다.

- 칸 조각에 들어가는 것: 세트 초안과 종별 초안 캐시, 기술 선택, 컷 고정 필드 전부(고정 목록·순번·기준 갈래·성격·예산) — 곧 `draft`, `draftCache`, `moveChoices`, `locks`, `lockSeq`, `lockBase`, `lockNature`, `lockSpTotal`.
- 세대 카운터(`generation`, `speciesGeneration`)와 `lockRevealNonce`는 칸 조각이 아니라 전역 단조 카운터로 둔다. 세대 카운터는 칸 전환·교체·복원 때 +1 한다(실행기가 세대가 같으면 재계산을 건너뛰므로, 칸별로 값을 되돌리면 다른 칸 세트로 바뀌어도 재계산이 안 될 수 있다). `lockRevealNonce`는 나타냄 신호를 낼 때만 +1 하고, 전환 때는 그 신호(`lockReveal`)를 비운다.
- 칸 조각에 넣지 않는 것: 한 번 보여 주고 사라지는 고정 연출 신호(나타냄·잘라냄 깜빡임 토큰)는 전환 시 비운다.
- 조각 필드 목록은 한 곳에만 두고, 타입 수준에서 "칸 조각 ∪ 전역 = 전체 상태"가 맞는지 컴파일 시 확인한다(필드 누락 방지).
- 빈 칸이 활성이면 세트 없음 상태로 계산 영역에 안내만 낸다.

(빌드 중 개정 2026-11-21)

### 결정 2. 상대 쪽 사용자 추가분은 전역에 남기고, 커스텀 상대 삭제는 모든 칸의 고정까지 연쇄한다

커스텀 상대·추가 배분·핀 배분·스피드 추가는 지금도 세트와 무관한 단일 목록이라 그대로 전역이다. 커스텀 상대 삭제 액션은 지금의 추가/핀 배분 연쇄 삭제에 더해, 최상위(활성) 고정과 보관함 각 칸의 고정에서 그 (출처 custom, 상대 id)를 대상으로 하는 고정을 지운다. 지운 뒤 각 칸의 고정 순번·기준 갈래가 남은 고정과 맞지 않으면 그 칸의 고정 해제 규칙과 같은 방식으로 정리한다.

### 결정 3. 브라우저 저장은 버전 붙은 한 덩어리, 읽을 때 검증하고 실패하면 버린다

- 브라우저 로컬 저장소의 키 하나에 `{형식 버전, 레귤레이션 id, 파티(6칸 조각·활성 칸), 전역 상대 목록}`을 JSON으로 저장한다. 화면 설정(탭·필터·정렬·메타 월)은 이번에 저장하지 않는다(PRD 범위 밖, 후속 여지).
- 쓰기는 상태 변경 뒤 짧게 묶어(디바운스) 한 번에 한다. 연출 신호·계산 캐시는 저장하지 않는다.
- 읽기: 버전이 다르거나 JSON·모양 검사에 실패하면 통째로 버리고 기본 상태(R23)로 시작한다. 레귤레이션 id가 현재와 다르면 세트는 살리고, 이름 색인으로 풀리지 않는 필드만 비운다(가져오기와 같은 규칙, 결정 4).
- 저장소 접근 자체가 막혀도(사생활 모드 등) 예외를 삼키고 메모리로만 동작한다.
- 세트는 지금 초안 모양(표시 라벨 포함) 그대로 저장한다. 라벨이 데이터 갱신으로 바뀌면 읽을 때 이름 색인이 id·라벨 양쪽을 받으므로 대부분 복원되고, 안 되면 그 필드만 빈다.

### 결정 4. PokePaste 해석은 순수 함수 두 단계(텍스트 → 영어 이름 세트 → 앱 세트)로 둔다

- 링크 정규화: pokepast.es의 16자리 16진 id를 뽑고 `/raw`를 브라우저에서 직접 받는다(교차 출처 허용 확인, notes). 서버 중계는 두지 않는다.
- 1단계(텍스트 해석, 데이터 무관): Showdown 내보내기 블록을 빈 줄로 나눠 종 줄(애칭 `별명 (종)`·성별 `(M)/(F)`·`@ 도구`), 특성, 성격, 노력치 줄, 기술 줄을 영어 문자열로 뽑는다. 레벨·개체값·테라 등 나머지 줄은 버린다.
- 2단계(앱 세트로 변환, 데이터 의존): 현재 레귤레이션 이름 색인으로 영어 이름을 id로 풀고, 초안이 요구하는 표시 라벨로 바꾼다. 도구가 메가 표의 스톤이면 (기본 종, 스톤)으로 메가 폼을 찾아 지금의 메가 선택 경로와 같은 초안을 만든다. 풀리지 않는 항목은 비우고 보고 목록에 적는다. 종이 안 풀리면 그 칸을 비운다.
- 노력치 줄 값은 SP로 읽는다. 능력치당 또는 합계 상한을 넘으면 그 포켓몬 SP를 모두 비우고 보고한다(PRD R18).
- 가져오기는 파싱·변환이 모두 끝난 뒤 한 액션으로 파티를 교체한다. 받기·해석 실패는 상태를 건드리지 않는다.

### 결정 5. 헤더 파티 줄은 사용자 지정 배치를 그대로 쓰고, 칸 순서 변경은 네이티브 끌기 + 키보드 대체로 한다

- 배치: 헤더 한 줄에 왼쪽 정사각형 6칸, 오른쪽 링크 입력·가져오기 버튼과 파티 비우기. 좁은 화면에서는 입력 묶음이 다음 줄로 내려간다. 칸 안 포켓몬 이미지는 기존 포켓몬 아이콘, 오른쪽 아래 도구는 기존 도구 마크를 겹쳐 쓴다. 칸 비우기(×)는 칸에 마우스를 올리거나 포커스했을 때 보인다.
- 순서 변경: 새 의존성 없이 브라우저 기본 끌어 놓기를 쓰고, 키보드는 칸에 포커스한 상태에서 좌우 이동 단축키로 같은 액션을 부른다.
- 확인 단계(파티 교체·파티 비우기)는 브라우저 기본 확인창이 아니라 앱 안 작은 확인 팝오버로 한다(기존 팝오버 패턴 재사용, E2E에서 다루기 쉬움).

## 선택지

### 선택지 A: 활성 칸은 최상위, 나머지는 보관함 (결정 1 채택)

- 장점: 기존 리듀서·셀렉터·카드 계산 경로가 최상위 필드를 그대로 읽으므로 손대는 곳이 칸 전환·가져오기·삭제 연쇄·저장으로 좁다. 한 마리 기본 상태의 계산 경로가 바뀌지 않아 N6을 지키기 쉽다.
- 단점: 칸 조각 필드 목록이 실제 상태와 어긋나면 전환 때 상태가 새거나 섞인다(타입 검사로 막음). 전역 연쇄(결정 2)는 최상위와 보관함 두 곳을 모두 훑어야 한다.

### 선택지 B: 모든 칸을 배열로, 활성 칸은 인덱스로 참조

- 장점: 모양이 정규적이고 연쇄 삭제가 배열 한 번 순회로 끝난다.
- 단점: 세트·고정을 읽는 모든 리듀서 분기·셀렉터·컴포넌트를 "활성 칸에서 읽기"로 바꿔야 한다(컷 고정 단위가 막 넣은 넓은 표면). 변경 범위가 커서 회귀 위험과 리뷰 비용이 크다.

### 선택지 C: 칸마다 리듀서 인스턴스를 따로

- 장점: 칸 격리가 자연스럽다.
- 단점: 전역 목록·연쇄 삭제를 칸 사이에 동기화해야 하고, 저장·가져오기가 여러 인스턴스를 조율해야 한다. 이점에 비해 복잡하다.

저장(결정 3): 브라우저 로컬 저장소 단일 키(채택) / IndexedDB(용량은 크지만 비동기·코드량 증가, 데이터가 수십 KB라 불필요) / URL 해시(공유엔 좋지만 고정·전역 목록까지 담기엔 길고 비목표인 공유에 해당).

해석(결정 4): 직접 작성한 작은 파서(채택) / Showdown 패키지의 팀 가져오기 도구 의존성 추가(형식 처리는 견고하지만 의존성이 크고 챔피언스 SP 해석·메가 매핑은 어차피 앱 쪽 규칙이 필요).

## 선택 근거

- 결정 1은 컷 고정 단위가 세트 딸림 상태를 넓게 깔아 둔 직후라, 읽는 쪽을 건드리지 않는 A가 회귀 위험이 가장 낮다. 칸 조각 목록을 한 곳에 두고 타입으로 맞춤을 확인하면 A의 주된 위험(필드 누락)을 컴파일 단계에서 막을 수 있다.
- 결정 2는 사용자 결정(전역 공유)과 앞 단위의 미결 과제("대상 없음" 고정)를 한 번에 정리한다.
- 결정 3은 데이터가 작고 동기 읽기가 첫 화면 복원에 유리하다. 버전·검증·실패 시 버림으로 N4·R24를 충족한다.
- 결정 4는 두 단계로 나눠 1단계를 데이터 없이, 2단계를 레귤레이션 스냅샷만으로 테스트할 수 있다(N5). 서버가 필요 없는 것은 교차 출처 허용 확인으로 뒷받침된다.
- 결정 5의 배치는 사용자가 지정했다. 끌기 라이브러리를 넣지 않는 것은 6칸 한 줄 재배치에 과하기 때문이다.

## 결과

### 긍정적 영향

- 파티 단위 작업이 가능해지고, 다음 요약 탭은 보관함 + 활성 조각을 순회하면 6마리 전부를 계산할 수 있다.
- 커스텀 상대 삭제 시 남던 "대상 없음" 고정이 사라진다.
- 새로고침해도 작업이 남는다.

### 부정적 영향 / 트레이드오프

- 칸 조각 필드를 새로 추가하는 이후 작업은 그 목록에 함께 넣어야 한다(지식 불변식으로 등록 예정).
- 저장 형식 변경 시 버전을 올리면 기존 사용자 파티가 사라진다(마이그레이션은 필요해질 때 추가).
- 비활성 칸의 고정은 다시 활성이 될 때 재계산된다. 그사이 상대·전역 목록이 바뀌면 활성화 때 고정 상태(도달 불가 등)가 달라질 수 있다 — 기존 재계산 규칙(경고 강등)을 따른다.

- [ ] 리듀서 단위 테스트: 칸 전환 왕복 후 조각 동일, 전환이 고정을 풀지 않음, 커스텀 상대 삭제가 보관함 칸의 고정까지 지움, 가져오기가 전역 목록을 유지함.
- [ ] paste 해석 단위 테스트: 고정 표본(메가스톤·성별 표기·애칭·미지원 항목·SP 초과·6마리 초과/미만·빈 paste)과 링크 정규화 변형.
- [ ] 저장 테스트: 왕복 복원, 버전 불일치·깨진 JSON·저장소 예외에서 기본 상태.
- [ ] 봉인 fixture(무고정 동일성)가 변경 없이 통과한다(N6).
- [ ] E2E: 가져오기(네트워크 응답 가로채기)·칸 전환 후 고정 유지·순서 변경·새로고침 복원.
