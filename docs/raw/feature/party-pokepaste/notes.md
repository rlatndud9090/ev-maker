# Notes: 파티 6칸과 PokePaste 가져오기

## 사용자 요청 (2026-11-20, 원문 요지)

1. PokePaste 링크만 넣으면 6마리 정보를 파싱해 세팅.
2. 헤더의 'SP 구간 판정'·'레귤레이션 M-C…' 문구를 없애 공간 확보.
3. 그 자리에 정사각형 6칸 파티 목록 — 포켓몬 이미지 + 오른쪽 아래 도구 이미지(챔피언스 UI 형태). 클릭 시 포켓몬 전환, 각 포켓몬의 모든 상태(컷 고정 포함) 저장.
4. 상대 목록에 커스텀으로 추가한 데이터는 모든 포켓몬이 전역 공유.
5. 파티 줄 오른쪽에 PokePaste 링크 입력창 + '가져오기' 버튼.
6. (요약 탭) — 다음 단위로 분리하기로 함.

## PRD 인터뷰 결정 (2026-11-20)

- 저장: 브라우저에 저장(파티·컷 고정·전역 상대 목록).
- 상대 쪽 목록(커스텀 상대·추가 배분·핀 배분·스피드 추가)은 전부 전역 공유.
- 가져오기: 기존 파티가 있으면 확인 후 통째 교체.
- 칸 관리: 칸 비우기, 끌어서 순서 변경, 파티 비우기 모두 포함. 빈 칸을 누르면 새 포켓몬 입력.

## 조사

- pokepast.es `/<id>/raw`(text/plain)·`/<id>/json`(application/json) 모두 `access-control-allow-origin: *` (2026-11-20 curl 확인). 브라우저에서 직접 fetch 가능.
- 챔피언스 paste 표본 `https://pokepast.es/27afa251f1c9a8b7`(Wolfe Glick, M-B, 출처 DevonCorp "10 Teams to Try for Pokemon Champions Regulation M-B"): Showdown 내보내기 형식. `EVs:` 줄에 SP 값(예 `16 HP / 2 Def / 24 SpA / 24 Spe`, 능력치당 ≤32·합 66). `Level: 50`, `Basculegion (M)` 성별 표기, `Raichu @ Raichunite Y` 메가스톤.
- 현재 코드(탐색 결과 요약)
  - 헤더: 제목 h1과 레귤레이션 안내 문구가 제품 화면 헤더에 있음.
  - 상태: 단일 리듀서에 세트 하나. 컷 고정 필드·기술 선택이 세트에 딸린 상태이고, 포켓몬 종 변경 동작은 같은 기본 종이 아니면 고정을 전부 푼다 → 칸 전환은 이 경로를 타면 안 된다.
  - 저장: 현재 브라우저 저장·URL 상태 없음(모두 메모리).
  - 커스텀 상대·추가/핀 배분·스피드 추가는 이미 세트와 무관한 단일 목록. 컷 고정 대상 키가 상대 id(커스텀이면 roster id)를 참조 → 커스텀 상대 삭제 시 모든 칸의 고정 정리가 필요(R12, 앞 단위 후속 과제 "대상 없음" 해소).
  - 이름 해석: 데이터 항목마다 영어·한국어 이름이 있고, 이름 색인이 소문자 영어 이름·id·한국어 라벨을 받는다. 메가는 (기본 종, 폼, 스톤) 표가 있음. 성별 표기·애칭은 별도 처리 필요.
  - 이미지: 포켓몬 아이콘·도구 마크 컴포넌트 재사용 가능(도구 겹침 배치는 새 스타일).

## 기존 E2E 기대 변경 (2026-11-21)

- 헤더 h1 제거(R1)로 `speed-chart.spec.ts` AC7 클릭·터치 테스트의 바깥 누름 대상을 `h1` → `.my-set h2`로 바꿈(`popover.spec.ts`와 같은 방식). 바깥 누름 의미는 그대로 — 팝오버 밖, 상시 보이는 정적 제목.
- `speed-chart.spec.ts` AC26 마지막 단계: 이전 기대 "새로고침이면 스피드 추가 배지가 사라진다"를 R22(스피드 추가 목록 저장)에 맞춰 "새로고침 뒤에도 같은 개수로 남는다"로 반전. 약화·삭제 아님.
- `speed-chart-a11y.spec.ts` 도구 아이콘 겹침 검사에서 파티 바 칸 아이콘 제외(R3: 포켓몬 이미지 오른쪽 아래 겹침 배치가 의도).
- `product-perf.spec.ts`: 매 로드가 첫 방문이어야 하는 측정이라 로드 전 저장 키 `ev-maker:party`를 비움.

## 도구 아이콘 범위 확장 (빌드 중, 2026-11-21)

- 이유: 파티 칸이 모든 지닌 도구를 보여 주는데, 아이콘은 반감열매·화력 도구·스피드 배수 도구 42종뿐이라 대부분(자뭉열매·기합의띠·메가스톤 등)이 가방 표지로 나왔다. 그래서 받는 범위를 스냅샷 도구 전체로 넓혔다.
- 변경: `scripts/data/lib/images.mjs`의 고정 목록 `ITEM_ICON_IDS`를 `itemIconIds(snapshots)`(현재 `src/data/regulations/{id}/data.json` 도구 id 합집합)로 바꿨다. `gen:images` 결과 대상 166종을 모두 받았다(새로 124, missing 0, 1.24 MiB).
- 표시 규칙은 그대로다: 판정 카드는 계산에 효과를 준 도구만 표시한다(`src/cards/iconTargets.ts`, INV-261117-relevant-item-only). 그 대상 집합이 받는 목록의 부분집합이라는 점은 `src/ui/images.test.ts`가 검사한다.
- 고지: `sources.config.json` usage·`src/assets/item-icons/LICENSE`를 "현재 레귤레이션 도구 전체 166종(파티 칸 표시용, 2026-11-21 수집)"으로 고치고 `gen:snapshot`을 다시 돌렸다(레귤레이션 data.json은 바이트가 같다).
