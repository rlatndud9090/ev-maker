# PRD: 스피드 탭 개편

## 배경

SP 구간 표의 스피드 탭은 공격·방어 탭과 같은 "메타 카드 리스트"다. 상대의 S 배분 묶음마다 카드가 있고, 카드를 펼치면 내 S SP 0~32 칸마다 선공·동속·후공이 보인다. 랭크업 행과 스카프 행은 카드 안에 붙는다. 써 보니 다음 문제가 있었다.

- 스피드는 한 줄로 늘어선 값이다. 사용자가 알고 싶은 것은 "지금 배분으로 어디까지 추월하는가", "S를 몇 더 주면 다음 상대를 넘는가"다. 그런데 카드 리스트는 사용률 순이라, 상대들의 스피드 순서와 내 위치를 한 화면에서 볼 수 없다. 사용자는 카드를 하나씩 펼쳐 머릿속으로 줄을 세워야 한다.
- 스카프·랭크업·순풍처럼 조건이 붙은 스피드는 카드 안의 행으로만 보인다. 조건을 붙였을 때 그 상대가 줄의 어디로 올라가는지 드러나지 않는다.
- 날씨·필드 스피드 특성(쓱쓱·엽록소·모래헤치기·눈치우기·서핑테일)은 스피드 탭에서 전혀 다루지 않는다. 상위 단위(`damage-tabs-row-revamp`)가 스피드 탭 개편과 함께 후속으로 미뤘다.
- 이미 쓰이는 스피드 비교 도구들(실수치 순 목록 + 내 위치 구분선, 같은 실수치 묶기, 조건별 별도 항목 + 태그)도 같은 결론을 가리킨다(notes "리서치").

이와 별개로, 공격·방어 탭은 상대 도구(반감열매·화력 도구)를 이름 옆 작은 아이콘으로 보인다. 처음에는 포켓몬 챔피언스의 박스·파티 화면처럼 **포켓몬 이미지 오른쪽 아래에 도구 아이콘을 겹쳐** 전 탭에서 지닌 도구(메가스톤 포함)를 통일되게 보이기로 했다. 그러나 이 앱의 포켓몬 이미지가 작아 겹친 도구가 잘 보이지 않아(예: 검은 포켓몬에 검은안경) 겹침을 되돌리고 도구를 이미지 옆에 따로 두었다 (빌드 중 개정 2026-11-16 2차, 사용자 확인). 따로 둔 순간 계산과 무관한 도구(메가스톤, 스피드와 무관한 가정 세트 도구 등)는 공간만 차지한다. 그래서 전 탭에서 **그 줄·배지의 판정 계산에 실제로 효과를 준 도구만** 아이콘으로 보인다 (빌드 중 개정 2026-11-17 4차, 사용자 확인).

### 이 단위로 없어지는 기존 표시

사전 승인 때 놓치지 않도록 모아 둔다(상세는 R12).

- 스피드 탭의 메타 카드 리스트 전체: 간단행, 펼친 상세(왼쪽 배분 목록·오른쪽 판정 행), 결과 배지(선공·동속·후공), 행 종류 배지, 목표 문구 표시 위치.
- 스피드 탭의 배분 직접 추가 폼, 배분 고정(핀), 배분 선택 메뉴(배분 추가는 차트 배지 상세의 조작으로 옮겨 간다, R15).
- 스피드 탭에서 5% 이상 배분 묶음을 전부 카드로 내던 규칙(포켓몬마다 1위 배분 하나만 기본 배지, R3).
- 스피드 탭의 "상대 순풍" 토글(조건 배지 필터로 옮겨 간다, R8).
- 공격·방어 탭 메가 상대 기본 줄의 메가진화 문양과 전 탭의 계산 무관 도구 표시(R13). 변형 줄(반감열매·화력 도구)의 이름 옆 도구 아이콘은 그대로 남는다 (빌드 중 개정 2026-11-17 4차, 사용자 확인).

## 목표

- [ ] 사용자가 스피드 탭 한 화면에서 상대들을 실수치 순서로 보고, 현재 배분의 기준선을 경계로 추월하는 상대와 추월당하는 상대를 바로 구분할 수 있다.
- [ ] 사용자가 상대 하나를 가리키면, 그 상대를 추월하려면 내 S가 최소 얼마여야 하는지 성격 무보정·상승 두 경우로 알 수 있다.
- [ ] 스카프·랭크업·순풍·날씨/필드 같은 조건이 붙은 상대 스피드가 같은 줄 위의 별도 배지로 보이고, 사용자가 조건 종류별로 켜고 끌 수 있다.
- [ ] 전 탭에서 그 줄·배지의 판정 계산에 효과를 준 도구만 아이콘으로 보인다. 공격·방어 탭은 변형 줄의 그 도구가 이름 오른쪽에, 스피드 차트는 스피드에 효과를 준 도구(구애스카프·검은철구 등)가 배분 표기 오른쪽에 보인다. 메가스톤과 계산 무관 도구는 보이지 않는다. 도구 이름은 툴팁과 읽기 이름으로 알 수 있다 (빌드 중 개정 2026-11-17 4차, 사용자 확인).

## 비목표

- 리스트 보기와 차트 보기의 전환 토글. 차트가 리스트를 완전히 대체한다(사용자 결정 2026-11-15).
- 내 쪽 S0~S32 눈금이나 칸별 판정 표시. 내 쪽은 현재 배분 기준선 하나뿐이다(사용자 결정 2026-11-15).
- 트릭룸(순서 반전) — 상위 단위부터 비목표다. 후속 단위.
- 마비 등 상태이상 조건 배지, 퀵풋 조건 — 후속 단위.
- 고대활성·쿼크차지·슬로스타트 같은 조건부 특성의 지원. 앱 공식이 거부하는 상대는 R9로, 내 세트는 R4로 다룬다.
- 곡예(Unburden) 효과. 곡예는 앱 공식이 거부하지 않아 효과 없이 기본 실수치로 축에 놓이고 경고하지 않는다(상세 안내 여부는 열린 질문 15). 지원은 후속.
- 선공기·우선도 표시. 스피드 차트는 같은 우선도 안에서의 순서만 다룬다.
- 날씨·필드의 일반 입력(실제 날씨 설정). 이번 날씨 배지는 "파트너가 날씨를 깔았다고 가정한" 조건 배지일 뿐이다. 대미지 판정의 날씨 규칙(공격측 특성에서만 유도)은 바꾸지 않는다.
- 조건 두 개 이상을 함께 거는 배지(스카프+순풍, +1+비 등). 조건 하나를 1회 거는 기존 규칙을 따른다.
- 방어 탭의 "내가 확실히 빠름" 판단 규칙 변경. 공격측 날씨를 반영하는 그 규칙은 그대로다.
- 스피드 계산 엔진의 배수 적용 순서 변경. 현재 앱 공식을 유지한다(검증은 비기능 요구로 둔다).
- 선택·필터 상태의 새로고침 후 보존. 지금처럼 새로고침하면 초기화된다.
- 내 랭크업(+1/+2) 토글로 기준선·최소 S를 올리는 기능(사용자 결정 2026-11-15, 후속).
- 내 도달 범위(S0 무보정~S32 상승) 띠 표시(사용자 결정 2026-11-15). 차트는 표시 중인 배지와 내 실수치 줄만 만든다(ADR 1).

> 상세 루브릭·부검·예시·지칭 규칙: `harness/templates/examples/README.md`.

> **용어**
> - **실수치** = 앱 스피드 공식(랭크 → 순풍 → 특성 → 도구 → 반올림)으로 낸 최종 스피드 값. 999 상한은 없다.
> - **배분 묶음** = 상대 S의 (SP, 성격 보정 상승/무보정/하락) 묶음. 상위 단위의 카드 단위와 같다.
> - **기본 배지** = 조건 없이 배분 묶음 하나의 실수치를 나타내는 배지.
> - **조건 배지** = 같은 상대·같은 배분 묶음에 조건 하나(랭크업 수단, 스카프, 순풍, 날씨/필드)를 건 실수치를 나타내는 배지.
> - **배분 표기** = 공격·방어 탭의 배분 표기와 같은 화살표 방식이다. "S32↑"(SP 32·상승 성격), "S20"(무보정, 기호 없음), "S0↓"(하락). 화살표의 색·기호는 공격·방어 탭 표기를 재사용한다. 접근 이름에는 "성격 상승/무보정/하락" 텍스트가 들어간다. 조건 배지 중 날씨/필드·랭크업·순풍은 뒤에 조건 태그가 붙는다(예: "S32↑ +1", "S20 비"). 스카프 배지는 태그 없이 구애스카프 이미지로 구분하고, "스카프 아닌 최다 도구" 배지는 태그·도구 표시 없이 배분 표기만 보인다(R7) (빌드 중 개정 2026-11-17 4차, 사용자 확인).
> - **기준선** = 내 현재 SP·성격·도구·특성으로 낸 내 실수치 위치(조건 없음, R4).
> - **추월** = 내 실수치가 상대보다 엄격히 크다. 같으면 **동속**이고 추월이 아니다.

### 기능 요구사항

#### R1. 차트가 카드 리스트를 대체 (사용자 결정 2026-11-15)

- [ ] 스피드 탭 본문은 세로 스피드 차트 하나다. 메타 카드 리스트는 스피드 탭에서 없어지고, 리스트로 돌아가는 토글도 없다.
- [ ] 공격·방어 탭은 카드 리스트 그대로다(도구 표시 방식만 R13으로 바뀐다).

#### R2. 세로축과 배치

- [ ] 세로축은 실수치다. 위가 빠르다. 상대 배지는 자기 실수치 높이에 놓인다.
- [ ] 실수치가 같은 배지는 한 줄에 가로로 나란히 놓고, 넘치면 같은 실수치 묶음 안에서 줄을 바꾼다. 실수치 라벨은 그 묶음에 한 번만 붙는다. 같은 줄 안 배지 순서는 배분 묶음 점유율 내림차순이고, 같으면 기본 배지가 조건 배지보다 앞, 그다음 상대 이름 가나다순이다. 묶음 목록에서 골라 추가한 배지(R15)는 그 묶음 점유율로 같은 규칙을 따른다(점유율이 있는 래더 배지). 점유율이 없는 배지, 즉 R15에서 임의 입력으로 추가한 배지와 목록 밖 타겟은 같은 줄의 점유율 있는 래더 배지 뒤에 놓는다. 그 안에서는 임의 추가 배지가 먼저, 다음이 목록 밖 타겟이며, 각각 추가 순이다.
- [ ] 배지·실수치 라벨·기준선 라벨은 서로 겹쳐 가리지 않는다. 실수치가 1~2만 달라도 이웃 줄 사이에 최소 줄 간격을 보장한다(이때 화면 간격의 비례는 깨질 수 있다).
- [ ] 표시 중인 모든 배지와 기준선이 줄로 놓이고 어떤 배지도 잘리지 않는다. 내 도달 범위는 따로 그리지 않는다(사용자 결정 2026-11-15, ADR 1).
- [ ] 실수치가 다르면 화면에서 위아래가 실수치 순서를 지킨다. 화면 간격은 실수치에 비례하지 않는다. 실수치마다 같은 높이 줄 하나를 둔다. 줄마다 "윗줄과 차이" 숫자는 적지 않는다(실수치 라벨로 충분하다) (ADR 1) (빌드 중 개정 2026-11-16 2차, 사용자 확인).
- [ ] 차트가 화면 높이를 넘을 수 있으므로 다음을 만족한다. 차트는 자체 내부 스크롤 프레임이고, 프레임 안에서 고정되는 것은 기준선 띠뿐이다(ADR 1).
  - 스피드 탭을 처음 열면 기준선이 화면 안에 보인다.
  - 기준선은 SP를 바꾸거나 스크롤해도 늘 화면 안에 보인다(차트 프레임 위·아래 끝에 붙는 띠, ADR 1).

#### R3. 상대 배지 구성 (사용자 결정 2026-11-15)

- [ ] 배지는 왼쪽부터 상대 포켓몬 이미지, 배분 표기(조건 배지면 조건 태그까지), 도구 이미지 순으로 나란히 놓인다(예: 포켓몬 이미지 · "S32" · 구애스카프 이미지). 도구 이미지는 그 배지의 실수치에 효과를 준 도구가 있을 때만 있고, 포켓몬 이미지에 겹치지 않는다(R13). 예: 스카프 배지와 가정 세트 도구가 구애스카프인 기본 배지는 구애스카프, 검은철구면 검은철구. 가정 세트 도구가 스피드와 무관하거나(메가스톤·생명의구슬 등) 상대 특성이 도구 효과 무효(무딘손 등)면 도구 이미지가 없다 (빌드 중 개정 2026-11-17 4차, 사용자 확인).
- [ ] 래더 상대의 기본 배지는 포켓몬(래더 항목)마다 **점유율 1위 배분 묶음 하나**다(사용자 결정 2026-11-15). 상위 단위의 "묶음 기준(5%) 이상 전부 카드" 규칙은 스피드 탭에서 이 규칙으로 대체된다. 1위 묶음의 점유율이 묶음 기준 미만이어도 그 묶음이 기본 배지다(상세에는 점유율을 적지 않는다 (빌드 중 개정 2026-11-17 3차, 사용자 확인)). 1위 점유율이 같은 묶음이 둘 이상이면 실수치가 높은 묶음을 기본 배지로 한다.
- [ ] 다른 배분은 사용자가 직접 추가한다(R15).
- [ ] 상대 도구는 가정 세트 그대로다. 공격·방어 탭처럼 도구를 지우지 않는다. 메가 폼 배지는 메가 폼 이미지로 보이고, 읽기 이름·툴팁·상세에 메가 폼 이름이 있다. 메가스톤은 스피드에 효과가 없어 도구 이미지를 두지 않고, "메가" 태그 표지도 두지 않는다 (빌드 중 개정 2026-11-17 4차, 사용자 확인).
- [ ] 배지는 상대 이름을 읽기 이름에 담는다. 배지 안에는 모든 폭에서 이름 텍스트가 없고 이미지와 배분 표기만 보인다. 마우스를 올리면 브라우저 기본 툴팁(title)으로 상대 이름(메가 폼은 메가 폼 이름)이 뜬다(ADR 1) (빌드 중 개정 2026-11-16, 사용자 확인).

#### R4. 내 기준선 (사용자 결정 2026-11-15)

- [ ] 내 쪽은 현재 배분 기준선 하나만 그린다. 기준선에는 내 실수치와 현재 S 배분 표기가 붙는다.
- [ ] 기준선은 내 도구(구애스카프·검은철구 등)와 특성(구름보기·에어록의 날씨 무효 포함)을 반영하고, 날씨·필드 조건은 넣지 않는다. 내 순풍 토글을 켜면 순풍을 반영한다(R11).
- [ ] 내 S SP·성격·도구·특성을 바꾸면 기준선이 바로 새 위치로 움직이고, 배지의 추월·동속 상태(R5)가 따라 바뀐다.
- [ ] 내 세트를 앱 스피드 공식이 거부하면(계산 거부 특성·도구: 슬로스타트·고대활성·쿼크차지·교정깁스류 / 순서 변경 특성·도구: 선제공격·퀵드로·균사의힘·선제공격손톱·느림보꼬리·만복향로·애터열매 등) 기준선·추월 상태·최소 S를 내지 않는다. 대신 차트 머리 바로 아래에 "내 스피드 계산 불가" 또는 "내 행동 순서 변경"과 그 원인(특성·도구 이름)을 안내한다. 상대 배지는 실수치 높이에 그대로 놓이되 상태 표지 없이(중립) 보이고, 상세의 최소 S 자리에는 같은 안내가 보인다.

#### R5. 추월·동속 상태

- [ ] 기준선 아래 배지는 "추월", 기준선과 같은 실수치의 배지는 "동속", 위의 배지는 "추월당함" 상태다. 세 상태는 배지 배경색으로 보이고, 색만이 아니라 위치로도 구분된다: 추월·추월당함은 기준선 아래·위, 동속은 기준선 띠 안이다. 세 상태 모두 접근 가능한 이름에 상태 이름이 들어간다. 배지 안에 "동속" 텍스트 표지는 두지 않는다 (빌드 중 개정 2026-11-16 2차, 사용자 확인).
- [ ] 기준선과 같은 실수치의 배지 줄(동속 줄)이 있으면 기준선은 그 줄 높이에 함께 놓인다. 기준선 라벨은 동속 줄의 배지를 가리지 않는다.
- [ ] "추월 n · 동속 n · 추월당함 n" 같은 개수 요약은 화면에 두지 않는다. 표시 중인 배지 총수가 보이지 않아 개수만으로는 쓸모가 없다 (빌드 중 개정 2026-11-16 2차, 사용자 확인).

#### R6. 배지 상세(클릭으로 여닫기) (사용자 결정 2026-11-15, (빌드 중 개정 2026-11-17 3차, 사용자 확인))

- [ ] 상세는 클릭(터치 화면은 탭)으로만 여닫는다. 배지를 클릭하면 열리고, 같은 배지를 다시 클릭하면 닫히며, 다른 배지를 클릭하면 상세가 그 배지 것으로 바로 바뀐다. 키보드는 포커스한 배지에서 Enter/Space로 같게 여닫는다. 마우스를 올리거나 키보드 포커스를 옮기는 것만으로는 상세가 열리거나 바뀌지 않는다. 호버로 열기 전 지연을 두던 방식은 없앤다 (빌드 중 개정 2026-11-17 3차, 사용자 확인).
- [ ] 상세는 Esc와 바깥 클릭(터치 화면은 바깥 탭)으로도 닫힌다. 상세는 그 배지 줄 바로 아래에 펼쳐지는 인라인 상세다(ADR 1).
- [ ] 상세에는 다음만 있다 (빌드 중 개정 2026-11-17 3차, 사용자 확인).
  - 머리줄: 상대 이름(메가 폼 이름), 배분 표기와 조건 태그, 그 배지의 실수치. 추월 상태(추월·동속·추월당함)는 상세에 보이는 텍스트 표지로 두지 않고, 상세 머리의 색과 접근 이름으로만 나타낸다.
  - **추월에 필요한 내 최소 S**를 성격 무보정·상승 두 경우로: "추월: 최소 S20 / S12+". 내 도구·특성과 내 순풍 토글은 기준선과 같게 둔다. 0~32 안에서 닿지 않으면 그쪽은 "불가"다(예: "추월: 무보정 불가 / S30+"). 동속은 추월로 치지 않는다. 잔여 SP 예산 초과 표지(R12)와 내 세트 계산 불가 안내(R4)는 그대로 둔다.
  - 래더 상대 배지(기본·조건·추가 배지 모두)의 상세에는 "다른 배분 추가"(R15)가 있고, 추가한 배지(R15)의 상세에는 "지우기" 조작이 있다.
- [ ] 상세에 두지 않는 것: 배분 묶음 점유율(임의 입력 배지의 "직접 입력" 표기 포함), 조건 점유율(스카프·랭크업 기술·특성 채용률), 도구 이름 텍스트, "파트너 날씨 가정"·"도구 효과 없음" 같은 안내 문구 (빌드 중 개정 2026-11-17 3차, 사용자 확인). 도구 이름은 배지의 도구 이미지 툴팁과 접근 이름으로 알 수 있다(R13).

#### R7. 조건 배지 생성 규칙 (사용자 결정 2026-11-15)

같은 상대라도 조건마다 별도 배지가 그 실수치 높이에 놓인다. 랭크업·순풍·날씨/필드 배지는 조건 태그를 달고, 스카프 배지는 태그 대신 구애스카프 이미지로 구분하고, "스카프 아닌 최다 도구" 배지는 태그도 도구 이미지도 없다 (빌드 중 개정 2026-11-17 4차, 사용자 확인). 조건 배지는 그 상대의 **기본 배지(점유율 1위 배분 묶음)**에만 붙고, 사용자가 추가한 배분(R15)에는 붙지 않는다(사용자 결정 2026-11-15). 생성 자격은 다음과 같다.

- [ ] **랭크업**: 수단 자격은 상위 단위 랭크 수단 규칙을 따른다. 자기에게 거는 능동 수단만 쓰고, 래더 수단 점유율이 수단 기준(기본 10%) 이상이어야 한다. S를 올리지 않는 수단(칼춤 등)은 제외하고, 다른 능력치 하락이 섞인 수단(껍질깨기 등)은 S만 본다. 순풍은 랭크 수단이 아니다. 태그는 S 랭크 부호("+1", "+2")다. 상위 규칙과 다른 점(이 단위가 대체한다):
  - 상위 단위는 수단마다 카드 안 랭크 행을 두지만, 여기서는 같은 S 랭크 값의 수단이 둘 이상이면 배지 하나로 합친다. 상세에 수단 이름·수단별 점유율은 적지 않는다(R6 (빌드 중 개정 2026-11-17 3차, 사용자 확인)).
  - 상위 단위는 모든 배분 묶음 카드에 랭크 행을 두지만, 여기서는 점유율 1위 배분 묶음(기본 배지)에만 붙인다.
- [ ] **스카프**: 메가가 아닌 래더 상대에서 구애스카프 점유율이 툴바 통계 설정의 기존 "구애스카프" 기준 이상이면 "스카프" 배지를 단다. 그 기준의 기본값은 10%에서 **5%**로 바뀐다(사용자 결정 2026-11-15. 니치 전략 수준, 예: 펠리퍼 Bo1 5.5%가 들어온다). 이 기준은 스피드 탭 스카프 판단에만 쓰이며 사용자가 툴바에서 바꿀 수 있다. 툴바 "구애스카프 최소(%)"의 기본 표시값도 5로 바뀐다(전 탭 공통 툴바). 기본값 10%를 전제한 기존 테스트는 AC23 매핑에 적는다. 대표 도구가 이미 스카프면 반대로 "스카프 아닌 최다 도구" 배지를 단다. 두 배지 모두 조건 태그("스카프"·도구 이름·"도구 없음")가 없다. 스카프 배지는 배분 표기 오른쪽에 구애스카프 이미지가 있고, "스카프 아닌 최다 도구" 배지는 그 도구가 스피드에 효과가 없으면 도구 표시 없이 배분 표기만 보인다(효과를 주는 도구면 R13 원칙대로 그 도구) (빌드 중 개정 2026-11-17 4차, 사용자 확인). 메가 상대에는 없다.
- [ ] **순풍**: 표시 중인 상대마다 "순풍" 배지(×2)를 단다.
- [ ] **날씨/필드**: 상대 특성 분포에서 쓱쓱·엽록소·모래헤치기·눈치우기·서핑테일 중 하나의 점유율이 특성 기준(기본 10%, 열린 질문 3) 이상이면 그 조건의 배지를 단다. 태그는 조건 이름이다(비·쾌청·모래바람·설경·일렉트릭필드). 날씨 배지는 파트너가 날씨를 건다고 가정한 값이지만, 상세에 "파트너 날씨 가정" 문구는 두지 않는다(R6 (빌드 중 개정 2026-11-17 3차, 사용자 확인)).
  - 내 특성이 구름보기·에어록이면 날씨 배지는 만들지 않는다(날씨가 무효라 기본 배지와 같은 값이 된다). 서핑테일(필드)은 영향받지 않는다.
  - 날씨 배지는 상대에게만 날씨를 건다. 기준선은 R4대로 날씨 없음이다. 날씨 무효 판정은 내 특성(구름보기·에어록)으로만 한다. 날씨 배지의 상대 세트는 특성을 그 날씨 특성으로 둔 세트라 상대 쪽 무효 특성은 생기지 않는다. 이 계산 입력(상대 세트에만 날씨를 넣는 단독 계산, 무효 판정은 내 특성으로만)은 ADR 결정 2를 따른다.
- [ ] 목록 밖 타겟은 사용자가 고른 프리셋·커스텀의 도구·특성·기술을 점유율 조건 없이 쓴다(S를 올리는 랭크업 수단 기술이 있으면 랭크업 배지, 특성이 날씨·필드 스피드 특성이면 그 조건의 날씨 배지, 순풍은 R7 순풍 규칙). 스카프 배지는 만들지 않는다(도구가 이미 지정돼 있다).
- [ ] 조건 배지의 실수치도 앱 스피드 공식으로만 낸다. 기본 배지 값에 화면이 따로 배수를 곱해 내지 않는다.
- [ ] 조건을 걸어도 기본 배지와 실수치가 같은 조건 배지는 만들지 않는다.

#### R8. 조건 필터 (사용자 결정 2026-11-15)

- [ ] 스피드 탭에 조건 종류별 필터가 있다: 랭크업 · 스카프 · 순풍 · 날씨/필드. 켜면 그 종류의 조건 배지가 보이고 끄면 사라진다. 기본 배지와 추가 배지(R15)는 조건 필터와 무관하게 항상 보인다(상위 N·선택 필터는 R11·R15를 따른다).
- [ ] 기본값은 랭크업·스카프·날씨/필드 켜짐, 순풍 꺼짐이다(열린 질문 2). 지금의 "상대 순풍" 토글은 순풍 필터로 대체된다.
- [ ] 필터 상태는 탭을 오가도 유지되고, 새로고침하면 기본값으로 돌아간다.

#### R9. 계산할 수 없는 상대

- [ ] 앱 스피드 공식이 계산을 거부하는 상대(슬로스타트·고대활성·쿼크차지·교정깁스류)와 행동 순서 자체를 바꾸는 특성·도구를 지닌 상대(선제공격·퀵드로·균사의힘·선제공격손톱·느림보꼬리·만복향로·애터열매 등)는 축 위에 놓지 않는다. 차트 아래 "순서 비교 불가" 영역에 이미지와 이유("계산 불가"·"행동 순서 변경")와 함께 나열한다(열린 질문 4).
- [ ] 조건 배지에서만 거부되는 경우(예: 그 조건의 대표 도구가 순서 변경 도구)는 그 조건 배지만 빠지고 기본 배지는 남는다.

#### R10. 목록 밖 타겟

- [ ] 목록 밖 타겟(프리셋·커스텀)도 차트에 배지로 놓인다. 래더 상대와 다른 배경색으로 구분되고, 배분 표기 옆에 "프리셋 n" 표지가 붙는다. 목록 밖 타겟을 추가·삭제하는 흐름은 지금과 같다.

#### R11. 공통 필터와 내 순풍

- [ ] 차트는 전 탭 공통 상위 N(기본 30)과 포켓몬 선택 필터를 그대로 따른다. 필터 밖 상대의 배지는 기본·조건·추가 배지 모두 보이지 않는다. 목록 밖 타겟은 지금처럼 상위 N·선택 필터와 무관하게 항상 보인다.
- [ ] 표시할 배지가 하나도 없으면(예: 선택 필터 결과가 비고 목록 밖 타겟도 없음) 차트 자리에 "표시할 상대가 없습니다"와 필터를 확인하라는 안내가 보인다. 이때도 기준선(내 실수치)은 보인다.
- [ ] 스피드 탭 툴바의 "내 순풍" 토글은 남는다. 켜면 기준선과 R6의 최소 S 계산에 순풍이 들어간다. 탭을 오가도 상태가 유지된다.

#### R12. 없어지는 스피드 탭 기능 (기존 계약 대체)

- [ ] 상위 단위 수용 기준 AC15의 "스피드 탭의 랭크·스카프 행은 이전과 같다"는 이 단위가 대체한다. 랭크·스카프 행은 R7의 조건 배지가 된다.
- [ ] 스피드 탭 카드의 배분 선택 메뉴·직접 추가 폼·고정(핀)은 없어지고, 배분 추가는 차트의 배지 단위 조작(R15)으로 바뀐다. 공격·방어 탭에서 만든 직접 추가 배분과 고정은 그 탭에서 지금처럼 동작하고, 스피드 탭에는 영향이 없다(오류 없음).
- [ ] 스피드 탭 카드의 결과 배지(선공·동속·후공)와 목표 문구("선공: 최소 S20 / S12+")는 R5 상태와 R6 상세의 "추월: 최소 …"로 옮겨 간다. 성격 2종·"불가" 표기는 같지만 목표는 바뀐다: 기존 목표 문구는 "현재 칸보다 한 단계 위"(후공이면 동속이 목표, 이미 선공이면 현재 유지)였고, 새 상세는 항상 **엄격 추월**에 필요한 최소 S다(사용자 결정 4 "S몇부터 추월"). 잔여 SP 예산을 넘는 값은 그 SP 값(예: "S28")에 예산 초과 표지를 붙인다(ADR 결정 2). AC7b의 기존 결과 고정 표는 추월 목표 사례끼리 비교하고, 동속 목표·현재 유지 사례는 "규칙 변경으로 결과 다름"으로 따로 고정한다.
- [ ] 상위 단위 랭크 행 규칙 중 "수단별 행"과 "모든 묶음 카드에 행"은 R7 랭크업의 "상위 규칙과 다른 점"으로 대체된다.

#### R13. 도구 표시 — 계산에 관여한 도구만, 포켓몬 이미지 옆 나란히 (사용자 결정 2026-11-15, (빌드 중 개정 2026-11-17 4차, 사용자 확인))

- [ ] 원칙: 탭마다 그 줄·배지의 판정 계산에 실제로 효과를 준 도구만 아이콘으로 보인다. 지닌 도구라도 그 계산에 효과가 없으면(메가스톤, 스피드 탭의 스피드 무관 도구, 도구 효과 무효 특성의 도구) 보이지 않는다. 그래서 같은 포켓몬이라도 탭마다 도구 표시가 다를 수 있다(예: 공격 탭 기본 줄은 도구 없음, 스피드 기본 배지는 가정 세트 도구가 구애스카프일 때만 구애스카프). 의도된 차이다 (빌드 중 개정 2026-11-17 4차, 사용자 확인).
- [ ] 도구 아이콘은 포켓몬 이미지 위에 겹치지 않는다. 처음에는 포켓몬 이미지 오른쪽 아래에 겹치기로 했으나, 이 앱의 포켓몬 이미지가 작아 겹친 도구가 잘 보이지 않아(예: 대도각참에 검은안경, 둘 다 검정) 되돌렸다 (빌드 중 개정 2026-11-16 2차, 사용자 확인).
- [ ] 적용 위치와 자리(이 목록이 전부다):
  - 공격·방어 탭 카드의 간단행·상세: 포켓몬 이름 오른쪽. 이 단위 이전 이름 옆 도구 아이콘의 크기·자리 그대로다.
  - 스피드 차트 배지(목록 밖 타겟 배지, 기준선 띠 안 동속 배지 포함): 배분 표기(조건 태그 포함) 오른쪽(R3).
  - "순서 비교 불가" 영역: 포켓몬 이미지 옆에 나란히(겹치지 않음). 스피드 배지 상세 머리는 포켓몬 이미지 없이 R6의 머리줄(이름, 배분 표기·도구 이미지(배지와 같은 관여 도구일 때만 (빌드 중 개정 2026-11-17 4차, 사용자 확인))·조건 태그, 실수치)만 둔다(바로 위 배지에 포켓몬 이미지가 있다) (빌드 중 개정 2026-11-17 3차, 사용자 확인). 불가 영역은 원인이 도구일 때만 그 도구를 보이고, 원인이 특성이면 도구를 보이지 않는다 (빌드 중 개정 2026-11-17 4차, 사용자 확인).
  - 포켓몬 선택 필터 목록과 목록 밖 타겟 추가·관리 UI는 도구 개념이 없어 도구를 보이지 않는다.
- [ ] 도구 아이콘 크기는 공격·방어 탭 이름 옆 아이콘 크기 수준이다(스피드 배지·불가 영역도 같은 수준 (빌드 중 개정 2026-11-17 3차, 사용자 확인)). 도구가 없으면 아무것도 두지 않는다.
- [ ] 효과가 무효화된 도구(예: 무딘손 상대의 구애스카프)는 계산에 효과가 없으므로 보이지 않는다. 배지의 "도구 무효" 표지도 두지 않는다 (빌드 중 개정 2026-11-17 4차, 사용자 확인). 스피드 차트 상세에는 "도구 효과 없음" 안내를 두지 않는다(R6 (빌드 중 개정 2026-11-17 3차, 사용자 확인)). 실수치는 앱 공식대로 도구 효과 없이 낸다.
- [ ] 무엇을 보이는가:
  - 공격·방어 탭의 변형 줄(반감열매 줄·화력 도구 줄): 그 도구.
  - 공격·방어 탭의 기본 줄과 그 밖의 변형 아닌 줄: 계산에 도구가 없으므로 없다. 메가 폼 기본 줄에도 메가진화 문양을 두지 않는다. 메가스톤은 도구로서 판정 배수에 효과를 주지 않고, 메가 폼 이미지·이름으로 충분하다(열린 질문 5) (빌드 중 개정 2026-11-17 4차, 사용자 확인).
  - 스피드 차트(배지·기준선 띠 안 동속 배지·상세 머리): 앱 스피드 공식이 그 배지 세트에 도구 배수를 적용한 도구만(구애스카프·검은철구 등). 상대 특성이 도구 효과 무효(무딘손 등)면 보이지 않는다. 이 판정은 앱 스피드 공식과 같은 기준(스피드 도구 배수 표·도구 효과 무효 특성 목록)으로 하고, 화면이 도구 목록을 따로 두지 않는다(ADR 결정 4). 메가스톤·생명의구슬 등은 보이지 않는다 (빌드 중 개정 2026-11-17 4차, 사용자 확인).
  - "순서 비교 불가" 영역: 원인이 도구일 때만 그 도구 (빌드 중 개정 2026-11-17 4차, 사용자 확인).
- [ ] 기존 변형 줄 표지의 성질을 유지한다: 접근 가능한 이름은 "OO 지닌 경우", 도구 이름은 아이콘 툴팁과 읽기 이름에만 있고 점유율은 적지 않으며, 줄 높이는 다른 줄과 같다(상위 단위 사용자 결정 2026-11-14). 식별 속성도 이 단위 이전과 같다.
- [ ] 도구 아이콘이 카드 클릭·펼침 동작을 바꾸지 않는다. 아이콘을 클릭해도 그 카드의 펼침·접힘이 이름 칸을 클릭할 때와 같다.
- [ ] 공격·방어 탭은 펼친 상세에 도구 이름을 텍스트로 보인다(열린 질문 13 기본값). 스피드 배지 상세에는 도구 이름 텍스트를 두지 않는다(R6) (빌드 중 개정 2026-11-17 3차, 사용자 확인).

#### R14. 도구 아이콘 자산

- [ ] 아이콘 대상 집합은 R13에서 아이콘으로 보일 수 있는 "관여 도구"의 합집합이다 (빌드 중 개정 2026-11-17 4차, 사용자 확인). 이 집합의 모든 도구는 오프라인에서 아이콘이 보인다.
  1. 기존 반감열매·화력 도구 아이콘 전체(공격·방어 변형 줄).
  2. 앱 스피드 공식이 배수를 적용하는 도구 전부(구애스카프·검은철구 등, 스피드 도구 배수 표 기준).
  3. 스냅숏 래더 전 종(상위 N 상한과 무관, "스카프 아닌 최다 도구" 후보 포함)과 목록 밖 타겟 프리셋 3종의 가정 세트 도구 중 "순서 비교 불가"의 원인이 되는 도구.
  - 메가스톤과 계산 무관 가정 세트 도구는 집합에서 빠진다. 메가진화 문양 이미지와 그 제3자 고지 항목은 쓰이지 않으므로 없앤다 (빌드 중 개정 2026-11-17 4차, 사용자 확인).
  - 이 집합 밖 관여 도구(커스텀 타겟에서 사용자가 고른 불가 원인 도구 등)는 대체 표지를 쓸 수 있다. 출처·판(버전) 고정과 제3자 라이선스 고지를 갱신한다.
- [ ] 아이콘이 없는 도구는 도구 아이콘 자리에 대체 표지가 보이고, 접근 가능한 이름과 툴팁에는 도구 이름이 그대로 있다. 이미지가 깨진 아이콘으로 보이지 않는다. 대체 표지는 공통 "도구" 표지(가방 모양) 한 가지이며, 받침 없이 그 그림만 도구 아이콘 자리에 둔다(ADR 5) (빌드 중 개정 2026-11-16 2차, 사용자 확인). 대체 표지는 아이콘 없는 관여 도구에만 쓰인다 (빌드 중 개정 2026-11-17 4차, 사용자 확인).

#### R15. 차트에서 배분 추가 (사용자 결정 2026-11-15)

- [ ] 래더 상대 배지의 상세에 "다른 배분 추가"가 있다. 그 포켓몬의 S 배분 묶음 목록(배분 표기·점유율, 점유율 내림차순)에서 하나를 고르면 그 묶음의 배지가 같은 차트에 추가된다. 목록에는 이미 차트에 있는 묶음이 표시만 되고 다시 고를 수 없다. 그 포켓몬의 S 배분 묶음 목록은 묶음 기준(툴바 "SP 배분")과 무관하게 스냅숏의 전 묶음이다. 스피드 탭에서 SP 배분 기준은 쓰이지 않는다.
- [ ] 묶음 목록에 없는 배분(임의 SP·성격)도 같은 자리에서 입력해 추가할 수 있다. 입력 규칙(SP 0~32, 성격 상승·무보정·하락)은 지금의 직접 추가와 같다. 입력한 배분이 묶음 목록에 있는 묶음이면 목록에서 고른 것과 같게 처리한다(같은 줄 순서 규칙에 그 묶음 점유율을 쓴다). "다른 배분 추가" 목록 안의 묶음 점유율은 고르기 위한 정보라 남는다 (빌드 중 개정 2026-11-17 3차, 사용자 확인). 이미 차트에 있는 묶음이나 이미 추가한 배분과 같은 SP·성격을 입력하면 추가되지 않고, "이미 있음" 안내가 보인다.
- [ ] 추가한 배지에는 "추가" 표지가 붙고, 상세에서 지울 수 있다. 추가한 배지는 기본 배지와 같은 가정 세트(도구·특성)를 쓰며 조건 배지는 만들지 않는다. 상위 N·선택 필터 밖으로 그 포켓몬이 빠지면 추가한 배지도 보이지 않고, 다시 들어오면 돌아온다.
- [ ] 추가한 배분은 탭을 오가도 유지되고 새로고침하면 사라진다. 스피드 탭에서 추가한 배분은 공격·방어 탭의 직접 추가 배분과 서로 영향을 주지 않는다.

### 비기능 요구사항

- [ ] **계산 일관성**: 배지 실수치와 기준선은 앱 스피드 공식으로만 계산한다. 배수 적용 순서(랭크·스카프·순풍·날씨)가 외부 도구 설명과 다를 수 있으므로, 경계 사례를 단위 테스트로 고정하고, notes에 경계 사례별 입력·기대값 표를 둔다. 경계 사례는 조건 하나에 가정 세트 도구·내 도구·내 순풍이 겹쳐 실제로 생기는 조합이다: 스카프×순풍(가정 세트 도구가 스카프인 상대의 순풍 배지, 내 스카프 + 내 순풍 기준선), +1×스카프, 날씨×스카프, 홀수 실수치의 반올림. 이것은 비목표인 "조건 2개를 거는 배지"와 다르다.
- [ ] **성능**: 상위 단위 예산을 지킨다 — 프로덕션 빌드·Chromium·상위 30·조건 필터 전부 켬 기준, 스피드 탭 처음 열기와 S SP 슬라이더 놓기(+4, 상한·잔여를 넘으면 −4. 상위 단위 성능 측정과 같은 조작) 각 10회에서 첫 표시 중앙값 ≤ 500ms, 전체 완료 중앙값 ≤ 3초, 계산 구간 최대 Long Task ≤ 100ms. 기존 측정(첫 카드 19ms, 완료 305ms)보다 나빠지면 notes에 원인을 기록한다. 공격·방어 탭은 도구 표시 개정 뒤에도 같은 예산을 지킨다.
- [ ] **깜박임 없음**: 계산이 진행되는 동안 이미 놓인 배지가 다른 실수치 높이로 옮겨 다니지 않는다. 계산 전 배지는 보이지 않거나 "갱신 중"이다. 판정은 AC25.
- [ ] **접근성**:
  - 스크린 리더는 차트를 실수치 내림차순 목록으로 읽는다. 기준선은 목록 안의 구분 항목("내 스피드 N, 이 아래는 추월")으로 읽힌다.
  - 배지는 키보드로 도달할 수 있다. 위아래 화살표는 이웃 실수치 줄로(같은 줄 안 같은 순번, 없으면 그 줄 마지막 배지로), 좌우 화살표는 같은 실수치 줄 안 이웃 배지로 이동한다(순서는 R2의 같은 줄 순서). Home/End는 가장 빠른·가장 느린 배지로 간다. 기준선 구분 항목은 포커스 대상이 아니다. Enter/Space로 상세를 여닫고, 포커스 이동만으로는 상세가 열리거나 바뀌지 않는다 (빌드 중 개정 2026-11-17 3차, 사용자 확인). 차트는 탭 순서에서 한 자리만 차지한다.
  - 배지의 접근 가능한 이름에 상대 이름·배분 표기·조건·실수치·상태(추월/동속/추월당함)·계산에 효과를 준 도구(있을 때)가 들어간다 (빌드 중 개정 2026-11-17 4차, 사용자 확인). "추가"·"프리셋 n" 표지도 들어간다.
  - 상세의 "다른 배분 추가" 목록·입력·지우기는 키보드로 조작할 수 있다. 추가하면 포커스가 새 배지로, 지우면 같은 줄 이웃 배지(없으면 이웃 줄)로 옮겨 간다.
  - 기준선이 움직이면 "내 스피드 N"이 보조 기술에 알려진다(개수 요약은 알리지 않는다) (빌드 중 개정 2026-11-16 2차, 사용자 확인).
  - 상태·조건 태그는 색만으로 구분하지 않고, 라이트·다크 모두 글자 대비 4.5:1 이상이다.
- [ ] **반응형**: 400px 폭에서 차트가 화면 안에 들어오고 페이지 가로 스크롤이 생기지 않는다. 같은 실수치 묶음이 넘치면 줄을 바꾼다. 상세는 화면 밖으로 넘치지 않는다. 1280px에서도 배치가 깨지지 않는다.
- [ ] **오프라인**: 오프라인 상태에서도 차트·배지 이미지·도구 아이콘(또는 대체 표지)이 보인다.
- [ ] **검증 가능성**: 조건 배지 생성 규칙(R7)과 최소 S 계산(R6)은 화면 없이, 상대 데이터와 내 세트를 직접 넣은 단위 테스트로 재현할 수 있다.

## 수용 기준

**차트·배치**

- [ ] AC1. 스피드 탭을 열면 카드 리스트·배분 선택 메뉴·상세 펼침이 없고 세로 스피드 차트만 있다. 공격·방어 탭은 카드 리스트 그대로다(e2e).
- [ ] AC2. 차트의 배지가 위에서 아래로 실수치 내림차순이고, 실수치가 같은 배지는 같은 줄에 R2의 순서로 가로로 놓이며 실수치 라벨이 한 번만 보인다. 배지·실수치 라벨·기준선 라벨 중 어떤 두 요소도 화면에서 겹치지 않는다. 기준선 띠가 제자리(끝에 붙지 않은) 스크롤 위치에서 검사한다. 띠가 끝에 붙어 있을 때 띠 뒤로 지나가는 줄은 겹침으로 보지 않는다. 실수치가 1 차이인 이웃 줄을 포함한 데이터로 검사한다(e2e로 영역 교차 검사, 400px·1280px).
- [ ] AC3. 표시 중인 모든 배지(예: 스카프·+2 배지)가 자기 실수치 줄에 잘리지 않고 보이고, 기준선 띠가 내 실수치 줄에 있다(e2e). 내 도달 범위 띠는 없다.
- [ ] AC4. 래더 상대의 기본 배지가 포켓몬마다 정확히 하나이고 그 포켓몬의 점유율 1위 S 배분 묶음이며(1위 점유율이 5% 미만인 사례, 1위 점유율 동률이면 실수치가 높은 묶음인 사례 포함), 배분 표기가 "S32↑", "S20", "S0↓" 형식이다(무보정은 기호 없음, 접근 이름에 성격 상승/무보정/하락 텍스트) (단위 + e2e) (빌드 중 개정 2026-11-16 2차, 사용자 확인).

**기준선·상태·상세**

- [ ] AC5. 내 S SP를 바꾸면 기준선이 새 실수치 위치로 움직이고, 기준선 아래 배지가 "추월", 같은 실수치 배지가 "동속", 위 배지가 "추월당함"으로 바뀐다(상태별 배경색 유지). 세 상태 모두 배지 접근 이름에 상태 이름이 있고, 배지 안에 "동속" 텍스트 표지가 없다. 기준선에 내 실수치와 현재 S 배분 표기(예: "S32↑", 무보정이면 "S20")가 보인다. 동속 줄이 있으면 기준선이 그 줄 높이에 있다. 기준선 띠에 "추월 n · 동속 n · 추월당함 n" 요약이 없다(e2e) (빌드 중 개정 2026-11-16 2차, 사용자 확인).
- [ ] AC5b. 내 특성을 고대활성(계산 거부)으로, 다른 경우 내 도구를 선제공격손톱(순서 변경)으로 바꾸면 기준선·추월 상태가 사라지고 원인 이름이 든 안내가 보이며, 배지는 상태 표지 없이 보이고 상세의 최소 S 자리에 같은 안내가 있다. 되돌리면 원래대로 돌아온다(단위 1건 + e2e 1건).
- [ ] AC6. 내 도구를 구애스카프로 바꾸면 기준선이 ×1.5 위치(앱 공식 값)로 움직이고, 내 특성을 구름보기로 바꾸면 날씨 배지가 사라진다(e2e·단위).
- [ ] AC7. 배지를 클릭하면 상세가 열리고, 같은 배지를 다시 클릭하면 닫히며, 열린 채 다른 배지를 클릭하면 그 배지 상세로 바뀐다. 배지에 마우스를 올리거나(지연 시간을 넘겨 머물러도) 키보드 포커스만 옮기면 상세가 열리지 않는다. 상세는 Esc와 바깥 클릭으로 닫힌다. 상세에 상대 이름(메가 폼 이름)·배분 표기·조건 태그·실수치와 "추월: 최소 S… / S…+"가 보이고, 배분 점유율·조건 점유율·도구 이름 텍스트·"파트너 날씨 가정"·"도구 효과 없음" 문구와 보이는 추월 상태 텍스트 표지가 없다(e2e). 모바일 뷰포트(400px, 터치)에서 탭으로 열고 바깥 탭으로 닫힌다(e2e 1건) (빌드 중 개정 2026-11-17 3차, 사용자 확인).
- [ ] AC7b. 최소 S 단위 테스트: (a) 무보정·상승 각각 그 SP에서 내 실수치가 상대보다 엄격히 크고 그 SP−1에서는 아님, (b) 동속이 되는 SP는 추월로 치지 않음, (c) 0~32에서 닿지 않으면 "불가". 그리고 기존 스피드 카드를 지우기 전에, 기존 목표 문구 규칙의 결과를 기대값으로 고정한 사례 표(최소 6건: 양쪽 불가, 무보정만 불가, 동속 경계, 내 순풍 켬, 내 스카프, 상대 스카프 조건)를 notes에 만들고 새 결과가 그 표와 일치한다.
- [ ] AC8. 내 순풍 토글을 켜면 기준선과 상세의 최소 S가 순풍 기준으로 바뀌고, 탭을 오갔다 돌아와도 토글 상태가 유지된다(e2e). 내 순풍을 켠 채 상대 순풍 배지의 최소 S가 양쪽 순풍 ×2를 모두 넣은 앱 공식 값과 같다(단위 1건).

**조건 배지·필터**

- [ ] AC9. 단위 테스트로 조건 배지 생성 규칙이 확인된다: 랭크업(수단 점유율 10% 경계 포함·미만 제외, S 없는 수단 제외, 순풍은 수단 아님, 같은 랭크 값 수단 합침), 스카프(메가 제외, 툴바 구애스카프 기준 경계 — 기본 5%에서 정확히 5.0%는 포함·4.9%는 제외(실데이터 사례 5.5% 펠리퍼 포함), 기준을 바꾸면 따라 바뀜, 대표 도구가 스카프면 "스카프 아닌 최다 도구"), 날씨/필드(특성 점유율 기준 경계, 내 구름보기·에어록이면 날씨 배지 없음, 서핑테일은 남음), 순풍(표시 상대마다 하나), 기본 배지와 실수치가 같으면 만들지 않음, 조건 배지는 기본 배지(1위 배분 묶음)에만 붙고 추가한 배분에는 없음, 목록 밖 타겟(S를 올리는 랭크업 기술이 있으면 랭크업 배지, 날씨·필드 스피드 특성이면 날씨 배지, 스카프 배지는 없음). 랭크업의 "상위 규칙과 다른 점" 두 가지(같은 랭크 값 합침, 1위 배분 묶음에만)는 상위 단위 랭크 행 테스트를 대체하는 것으로 AC23 매핑에 적는다.
- [ ] AC10. 쓱쓱 특성 점유율이 기준 이상인 상대 하나에 "비" 태그 배지가 그 상대 점유율 1위 배분 묶음에 비 조건을 넣은 앱 공식 값 높이에 보인다. 상세에 "파트너 날씨 가정" 문구는 없다(e2e) (빌드 중 개정 2026-11-17 3차, 사용자 확인). 실데이터에 그런 상대가 없으면 고정 데이터로 e2e를 돌린다.
- [ ] AC11. 필터: 기본 상태에서 랭크업·스카프·날씨/필드 배지가 보이고 순풍 배지는 없다. 순풍 필터를 켜면 순풍 배지가 생기고, 각 필터를 끄면 그 종류 배지만 사라지며 기본 배지는 남는다. 필터를 바꾼 뒤 공격 탭을 다녀와도 필터 상태가 유지되고, 새로고침하면 랭크업·스카프·날씨/필드 켜짐, 순풍 꺼짐으로 돌아간다. 새로고침 직후 툴바 "구애스카프 최소(%)"가 5다(e2e).
- [ ] AC12. 조건 배지 실수치는 앱 스피드 공식 호출 결과와 같다. 단위 테스트로 조건 종류마다 기대값을 고정하고, 조건 배지는 조건 하나지만 가정 세트 도구나 내 도구·내 순풍과 겹쳐 생기는 스카프×순풍(스카프 지닌 상대의 순풍 배지, 내 스카프 + 내 순풍 기준선)·+1×스카프·날씨×스카프·홀수 반올림 경계를 고정한다. 이 사례의 입력·기대값 표가 notes에 있다. 무딘손 상대의 스카프 지닌 기본 배지는 도구 효과 없는 값이고 스카프 조건 배지가 생기지 않는다.

**계산 불가·목록 밖 타겟·공통 필터**

- [ ] AC13. 계산 거부 특성·도구 또는 행동 순서 변경 특성·도구를 지닌 상대가 축 위에 없고 "순서 비교 불가" 영역에 이유와 함께 보인다. 조건에서만 거부되는 경우는 그 조건 배지만 빠진다(단위 + e2e 1건).
- [ ] AC14. 목록 밖 타겟 프리셋 3종을 추가하면 각자 실수치 높이에 다른 배경색과 "프리셋 n" 표지로 보이고, 삭제하면 사라진다(e2e).
- [ ] AC15. 상위 N을 바꾸거나 포켓몬 선택 필터를 쓰면 차트 배지(기본·조건 배지 모두)가 그 범위로 바뀌고, 목록 밖 타겟 배지는 남는다. 선택 결과가 비고 목록 밖 타겟도 없으면 빈 상태 안내와 기준선이 보인다(e2e).
- [ ] AC16. 공격·방어 탭에서 직접 추가 배분·고정을 만든 뒤 스피드 탭으로 가도 오류가 없고, 다시 돌아오면 그 탭의 직접 추가·고정이 그대로다. 스피드 탭에서 추가한 배분은 공격·방어 탭에 나타나지 않는다(e2e).
- [ ] AC26. 래더 상대 배지 상세의 "다른 배분 추가"에서 (a) 묶음 목록의 다른 묶음, (b) 임의 SP·성격 입력으로 각각 배지를 추가하면 "추가" 표지와 함께 그 실수치 높이에 놓이고, 조건 배지는 생기지 않으며, 이미 있는 묶음은 다시 고를 수 없다. 임의 입력 배지의 상세에는 점유율도 "직접 입력"도 없다 (빌드 중 개정 2026-11-17 3차, 사용자 확인). 이미 차트에 있는 묶음이나 이미 추가한 배분과 같은 SP·성격을 다시 입력하면 추가되지 않고 "이미 있음" 안내가 보인다. 추가 배지는 기본 배지와 같은 도구 표시 규칙(R13: 스피드에 효과를 준 도구일 때만 배분 표기 오른쪽 도구 이미지 (빌드 중 개정 2026-11-17 4차, 사용자 확인))을 따르고, 기준선 대비 추월·동속·추월당함 상태와 상세의 "추월: 최소 …"가 보인다 (빌드 중 개정 2026-11-16 2차, 사용자 확인). 상세에서 지우면 사라진다. 탭을 오가도 남고 새로고침하면 사라진다. 상위 N을 줄이거나 포켓몬 선택 필터로 그 포켓몬을 빼면 추가 배지도 보이지 않고, 되돌리면 추가 배지가 다시 보인다(e2e).

## 열린 질문

각 항목은 기본값을 요구로 두었다. 사전 승인 전에 확인한다.

1. ~~조건 배지를 붙일 배분 묶음 범위~~ — **결정(2026-11-15)**: 포켓몬마다 1위 배분 하나만 기본 배지이고 조건 배지는 그 배지에만 붙는다(R3·R7). 스카프 기준은 툴바 기존 설정, 기본값 5%.
2. **조건 필터 기본 상태** — 기본값: 랭크업·스카프·날씨/필드 켜짐, 순풍 꺼짐(순풍은 상대 수만큼 배지가 늘고, 지금 상대 순풍 토글 기본도 꺼짐). 대안: 전부 켜짐 / 전부 꺼짐.
3. **날씨/필드 배지 자격** — 기본값: 상대 특성 분포에서 해당 특성 점유율 10% 이상(기존 랭크 수단 기준값 10% 재사용. 스카프 기준(기본 5%)과는 별개. 툴바 통계 설정에 별도 값을 둘지는 구현 판단). 대안: 대표 세트 특성일 때만.
4. **계산할 수 없는 상대** — 기본값: 축 밖 "순서 비교 불가" 영역에 이유와 함께 나열. 대안: 숨김 / 축 위에 무효 표시.
5. ~~공격·방어 탭 기본 줄 메가스톤 표시~~ — **결정 (빌드 중 개정 2026-11-17 4차, 사용자 확인)**: 메가 기본 줄에도 메가진화 문양을 두지 않는다(계산에 효과를 준 도구만 표시, R13). 메가 폼 이미지·이름으로 충분하다.
6. **내 포켓몬 이미지에도 도구 표시** — 기본값: 이번 범위는 상대 포켓몬 이미지뿐. 내 세트 표시에 이미지가 있으면 같은 방식을 쓸지 확인.
7. **내 날씨 스피드 특성** — 내가 쓱쓱 등일 때 기준선은 날씨 없음(R4)이라, 같은 비 가정에서 내 쪽도 ×2라는 점은 보이지 않는다. 기본값: 기준선은 날씨 없음 유지. 상세 안내 문구를 두지 않으므로(R6 (빌드 중 개정 2026-11-17 3차, 사용자 확인)) "내 쪽 날씨 미반영" 안내도 두지 않는다. 대안: 날씨 배지 상세의 최소 S를 내 날씨 특성까지 넣어 계산.
8. **축 간격** — 실수치와 화면 간격의 비례 방식(완전 비례 / 빈 구간 압축). 기본값 없음, ADR 디자인 결정 레인에서 시안 비교 후 결정.
9. **포켓몬 챔피언스의 실제 도구 아이콘 위치·크기** — 외부 자료로 확인하지 못했다. 겹침 방식 자체를 되돌려 이 질문은 닫혔다. 도구는 포켓몬 이미지 옆(공격·방어는 이름 오른쪽, 스피드 배지는 배분 표기 오른쪽)에 이름 옆 아이콘 크기 수준으로 둔다(R13·AC17) (빌드 중 개정 2026-11-16 2차, 사용자 확인).
10. ~~내 도달 범위 띠~~ — **결정(2026-11-15)**: 그리지 않는다. 그 구간을 위한 줄도 만들지 않는다(R2, ADR 1).
11. ~~내 랭크업 토글~~ — **결정(2026-11-15)**: 이번 단위 비목표(후속).
12. ~~요약 개수 단위~~ — **결정 (빌드 중 개정 2026-11-16 2차, 사용자 확인)**: 개수 요약을 화면·알림 어디에도 두지 않는다(R5).
13. ~~공격·방어 탭의 터치 화면 도구 이름~~ — **결정 (빌드 중 개정 2026-11-17 3차, 사용자 확인)**: 공격·방어 탭은 기본값대로 펼친 상세에 도구 이름을 텍스트로 보인다(점유율 없이). 스피드 배지 상세에는 도구 이름 텍스트를 두지 않고, 도구 이름은 배지 도구 이미지의 툴팁·접근 이름으로만 알 수 있다(R6·R13).
14. ~~직접 배분 추가의 대체 경로~~ — **결정(2026-11-15)**: 차트 배지 상세에 "다른 배분 추가" 조작을 둔다(R15).

## ADR 필요 여부

- **필요:** 다음이 다투는 durable decision이다. `$adr-helper`(UI-significant이므로 디자인 결정 레인 포함)에서 다룬 뒤 PRD·ADR을 한 번에 사전 승인받는다.
  1. **스피드 탭 화면 배치(디자인 결정 레인)** — 카드 리스트를 세로 차트로 대체하면서 정할 것: 축 간격(완전 비례 / 빈 구간 압축)과 최소 줄 간격, 같은 실수치 묶음 배치와 줄바꿈, 기준선 표현, 기준선 고정 위치, 차트 최대 높이·내부 스크롤·기준선 따라가기(또는 "내 위치로")·고정 요소, 배지 안 이름 텍스트 유무, 상세의 형태와 위치(팝오버 / 400px 아래쪽 시트), 조건 필터의 위치(툴바 / 차트 머리), "순서 비교 불가" 영역, 빈 상태, 내 세트 계산 불가 안내, 배지 상세의 "다른 배분 추가"(묶음 목록·임의 입력·"추가" 표지·지우기) 배치(팝오버 / 아래쪽 시트). 시안 비교가 필요하다.
  2. **차트 데이터 모델과 계산 경로** — 지금 행 스윕(내 SP 0~32 칸 판정) 모델을 그대로 두고 표시만 바꿀지, 배지(상대·묶음·조건 → 실수치) 단위 모델을 새로 둘지. 최소 S 계산 위치, 날씨 조건을 상대에게만 거는 계산 입력(지금 날씨는 양쪽 공통 입력이고 어느 쪽 세트든 구름보기·에어록이면 지워진다 — 무효 판정 주체를 내 특성으로 한정하는 방법), 내 세트 거부 시 처리 경로(R4), 기존 순풍 조건 입력과 조건 필터의 관계, 성능 예산 재검증이 함께 걸린다. 하위 항목: 없어지는 스피드 탭 배분 선택·직접 추가·고정 상태를 걷어내는 방식과, R15의 스피드 탭 추가 배분 상태(탭 이동 유지·새로고침 소멸, 공격·방어 직접 추가와 격리)를 탭별 상태 구조에 두는 방식(기존 직접 추가 상태 재사용 / 새로 둠).
  3. **조건 배지 생성 규칙의 위치와 임계값** — 랭크업·스카프·날씨/필드·순풍 자격 판단을 어디에 두고 기존 수단·스카프 규칙과 어떻게 공유할지, 툴바 "구애스카프" 기준 기본값 변경(10%→5%), 날씨 특성 임계값을 랭크 수단 기준값(10%) 재사용으로 할지 설정으로 노출할지.
  4. **도구 표시 공용 요소** — 전 탭이 공유할 도구 표시 단위의 구조(처음 "포켓몬 이미지 + 도구 겹침", 빌드 중 "이미지 옆 나란히"로 개정 (빌드 중 개정 2026-11-16 2차, 사용자 확인)). 기존 변형 줄 표지의 접근 이름·식별 속성·줄 높이 규칙 보존, 이미지 요소의 기존 구조를 전제한 검증과의 호환이 걸린다.
  5. **도구 아이콘 자산 확장** — R14 대상 집합을 산출·대조하는 방법, 메가스톤 아이콘 정책(종별 / 공통 — 메가스톤을 표시하지 않게 되어 없어짐 (빌드 중 개정 2026-11-17 4차, 사용자 확인)), 출처·판 고정, 라이선스 고지, 대체 표지의 한 가지 모양.
  6. **차트 접근성 구조** — 시각 배치(높이 배치)와 의미 구조(내림차순 목록·기준선 구분 항목·위아래·좌우·Home/End 이동·알림 영역)를 분리하는 방식.
  - 이전 초안의 "없어지는 스피드 탭 상태 처리"는 동작이 R12로 정해져 다툼거리가 약하므로 ADR 2 하위 항목으로 내렸다.
