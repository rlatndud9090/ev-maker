# ADR: 포켓몬 추가 UI/UX 개선

> 작성 고도: ADR은 "어떤 구조를 왜 골랐나"의 근거 저널이다. 코드 스니펫·전체 설계문서를 본문에
> 넣지 않는다(과대 ADR) — 상세 구현은 코드·별도 설계문서로 내린다. 사람은 중립 역할어로만
> 지칭하고 개인 호칭·별명은 넣지 않는다. 참고: `harness/templates/examples/README.md`.

> 범위: PRD "ADR 필요 여부"의 두 결정을 다룬다.
> - 결정 1 데이터 모델·판정 경계: 설계안 3개(최소 확장·통합 모델·파생 질의)를 심판이 비교해 파생 질의안을 권고했고, 사용자가 이를 확정했다(2026-11-18).
> - 결정 2 화면 배치: 디자인 결정 레인 시안(`./design-options.html`) 중 사용자가 대안 A를 골랐다(2026-11-18).
>
> 상위 ADR과의 관계는 이렇다.
> - `../speed-tab-revamp/adr.md` 결정 1 가운데 "상세(PRD R6)"의 형태·밀어내기 조항만 이 ADR 결정 3이 대체한다(인라인 상세 → 앵커 팝오버). 축·줄·기준선 띠·열기/닫기 규칙 등 결정 1의 나머지는 그대로 유효하다 (빌드 중 개정 2026-11-18, 사용자 확인).
> - `../speed-tab-revamp/adr.md`의 스피드 배지 상세 "다른 배분 추가" 조항은 그대로 둔다. 이 ADR은 그 판정·문구만 공통 규칙으로 바꾼다.
> - "범위 밖으로 빠진 상대의 추가 배지는 보이지 않는다"는 기존 동작(e2e AC26)은 이 ADR이 대체한다(결정 1, 사용자 확인 2026-11-18).

## 컨텍스트

- **PRD 요구**
  - '포켓몬 추가'에서 로스터 전체를 고르고, 이미 있는 포켓몬(메타·목록 밖)에는 그 탭 기준의 새 배분을 패널 안에서 더한다(R1~R3).
  - 같은 배분이 화면에 있으면 "이미 존재합니다 — [배분 표기]"로 막는다. 동일성은 핵심 능력치별 SP와 보정 부호다(R4). 공·방 추가 배분도 핵심 능력치별 보정 부호를 가진다 (빌드 중 개정 2026-11-19, 사용자 확인).
  - SP 범위 검사와 문구가 세 진입점(패널, 스피드 배지 상세 "다른 배분 추가", 카드 배분 메뉴 '직접 추가')에서 같다(R5·R9).
  - 목록 밖 포켓몬도 그 탭·분류 첫 프리셋을 기준으로 추가 배분을 가진다(R6).
  - 표시 범위 밖 메타 포켓몬은 배분을 더한 탭에만, 추가한 배분만 나타난다. 상위 N·선택 설정은 바뀌지 않는다(R7).
  - 추가 뒤 패널이 닫히고 새 배분으로 포커스가 간다. 탭을 바꿔도 고른 포켓몬은 유지된다(R8·R10).
- **현재 코드/데이터 제약**(조사 2026-11-18, notes "맥락")
  - 추가 배분은 두 갈래다. 공·방은 래더 전용 추가 배분 목록(탭·상대·분류·핵심 SP)에, 스피드는 스피드 전용 추가 배분 목록(상대·S SP·부호)에 담는다. 목록 밖 포켓몬은 고정 프리셋 3개만 있고 추가 배분 자리가 없다.
  - 메타 id와 목록 밖 로스터 id는 지금은 겹치지 않는다. 목록 밖 타겟이 메타에 있으면 계획이 충돌로 빼기 때문이다. 하지만 메타 월·매치 방식을 바꾸면 세션 안에서도 겹칠 수 있다.
  - 동일성·유효성 검사가 흩어져 있다. 리듀서 형식 검사 두 벌, 스피드 차트 추가 판정, 계획의 사용자 씨앗 검사, 카드 컴포넌트의 화면 비교식이 따로 있다. 문구도 진입점마다 다르다.
  - 스피드 추가 판정은 표시 중 래더 상대만 받는다(범위 밖·목록 밖은 invalid). 목록 밖 프리셋 배지는 비교하지 않는다.
  - 카드의 배분 추가·고정·삭제 조작은 래더 카드에만 있다. 카드 id에는 래더 출처가 고정으로 박혀 있다.
  - 공·방 분류와 핵심 능력치는 탭 계획 안에서만 계산된다. 공격 탭은 내 공격기가 정하고, 방어 탭은 상대 기술이 정한다.
  - 공·방 계획은 비동기 실행기를 거친다. 스피드 차트 모델은 동기 계산이다.
  - 앱 상태는 메모리 전용이다.
- **사용자 경험 제약**
  - 패널과 스피드 배지 상세는 화면을 밀어내지 않는 앵커 팝오버로 뜬다(결정 2·3). 처음에는 버튼 아래 펼침 영역이었으나, 공간을 차지하며 아래 내용을 밀어내고 가로로 너무 길다는 사용자 피드백으로 바꿨다 (빌드 중 개정 2026-11-18, 사용자 확인). 폭 400px에서 가로 스크롤 없이 써야 한다.
  - 키보드만으로 검색→선택→입력→추가/취소를 끝낼 수 있어야 한다.
- **검증 제약**
  - 중복·유효성 판정과 범위 밖 노출 규칙은 화면 없이 단위 테스트로 확인할 수 있어야 한다.
  - 기존 e2e의 문구 단언(스피드 "이미 있음 — …", 카드 "SP는 0~N 정수만 넣을 수 있습니다")과 AC26(범위 축소 시 추가 배지 사라짐)은 새 규칙에 맞게 갱신한다.

## 결정

### 결정 1. 추가 배분 데이터 모델과 판정 경계: 기존 추가 배분 목록에 대상 출처 판별자를 필수로 더하고, 범위 밖 노출은 계획 단계에서 파생하며, 중복·유효성 판정은 cards 계층의 순수 질의·판정 모듈 하나가 맡는다(파생 질의안)

- **상태.**
  - 공·방 추가 배분, 스피드 추가 배분, 배분 고정 항목은 지금 목록을 그대로 쓴다. 여기에 대상 출처(메타 래더 / 목록 밖)를 필수 값으로 더한다.
  - 목록 밖 포켓몬의 추가 배분도 같은 목록에 출처 "목록 밖"으로 담는다. 프리셋 편집 구조는 바꾸지 않는다.
  - 새 액션 종류는 만들지 않는다. 기존 추가·삭제·고정 해제 액션이 출처를 포함해 비교한다.
  - 리듀서의 형식 검사와 같은 항목 거름은 1차 방어선으로 남긴다.
  - 목록 밖 포켓몬을 지우면 그 출처·id의 추가 배분과 고정도 함께 지운다.
- **동일성·유효성 단일화.**
  - 추가 배분의 동일성 키는 탭·출처·상대·분류·핵심 SP·부호이고, ids 계층의 키 함수 하나로 모은다.
  - "0 이상 능력치당 최대 SP 이하 정수" 검사는 cards 계층의 함수 하나로 모은다. 리듀서·계획·스피드 차트·세 진입점이 모두 이 함수를 쓴다.
- **범위 밖 노출(R7)은 상태가 아니라 파생이다.**
  - 공·방 계획과 스피드 차트의 상대 선정이 세 집합을 함께 낸다: 표시 범위 안 래더, 이 탭에 추가 배분이 있는 범위 밖 래더, 목록 밖.
  - 범위 밖 래더는 "추가분만" 상대다. 1위 배분 가정은 나머지 값의 기준으로만 쓴다. 스피드는 점유율 1위 S 묶음(스카프 없는 세트)이고, 공·방은 첫 관측 묶음이며 없으면 대표 가정이다.
    - 스피드: 1위 기본 배지·조건 배지를 내지 않고 추가 배지만 낸다.
    - 공·방: 관측 묶음 카드를 만들지 않는다. 사용자 추가 카드와 그 반감열매·화력 도구 변형 카드는 범위 안과 같은 행(기본·랭크)을 그대로 가진다.
  - "추가분만" 상대는 씨앗 단계의 중복 기준 집합을 빈 집합에서 시작한다. 지금 씨앗 함수는 관측 키로 시작해 같은 키의 추가 배분을 버리는데, 이 상대에서 그대로 두면 1위 값이나 관측 묶음과 같은 SP를 넣었을 때 판정은 ok인데 카드·배지가 생기지 않는다. 판정 질의의 "표시 중 키"도 같은 정의를 쓴다.
  - 그래서 상위 N 안에서 추가한 배분도 상위 N을 줄이거나 선택 필터로 빠지면 "추가분만" 상대로 남는다(사용자 확인 2026-11-18, AC26 대체).
  - 마지막 추가 배분을 지우면 다음 계산에서 그 상대가 빠진다. 다른 탭과 상위 N·선택 값은 영향받지 않는다.
  - 스피드 차트의 범위 밖 처리는 별도 루프로 만들지 않는다. 같은 상대 루프에서 기본·조건 배지를 낼지만 가른다. 1위 가정 결정이 표시 중 상대와 어긋나지 않게 하려는 것이다.
  - 도구 제거(메가스톤 외), 반감열매·화력 도구 변형에는 추가 배분 씨앗만 들어간다.
- **판정 질의.**
  - cards 계층의 순수 모듈 하나가 "이 탭에서 이 포켓몬에 지금 표시된 배분 키, 더할 수 있는 분류·핵심 능력치" 질의와 추가 판정(ok / 이미 존재 / 잘못된 값 / 더할 배분 없음)을 낸다.
  - 질의는 탭 계획과 스피드 차트가 실제로 쓰는 씨앗 함수를 그 상대 하나에만 돌려 얻는다. 화면 표시 규칙과 중복 규칙이 갈라지지 않게 하려는 것이다. 표시 기준 미달 관측 배분 제외, 무보정 키와 보정 키의 구분, 목록 밖 프리셋 포함이 저절로 맞는다.
  - 공·방 분류·핵심 능력치 산출과 상대 단위 씨앗 생성은 탭 계획 안에서 공개 함수로 뽑는다. 패널과 탭 계획이 같은 규칙을 쓴다.
  - 판정은 앱 상태와 계산 입력만으로 동기로 실행한다. 비동기 계산 중인 직전 계획에 기대지 않는다. 계산 중에도 상태의 같은 키 추가 배분을 합집합으로 본다.
  - 문구는 app 계층의 함수 하나가 판정 결과에서 만든다. 세 진입점이 이 판정과 문구를 공유한다.
- **공·방 성격 보정 (빌드 중 개정 2026-11-19, 사용자 확인).**
  - 공·방 추가 배분은 핵심 능력치마다 보정 부호(상승·무보정·하락)를 가진다. 처음에는 "공·방 추가 배분은 늘 무보정"으로 정했으나, 사용자가 추가할 때 성격 보정을 넣고 싶다고 해 바꿨다.
  - 상태의 공·방 추가 배분 항목은 능력치별 SP와 함께 능력치별 부호를 담는다. 동일성 키도 이 부호를 쓴다.
  - 부호 규칙: H에는 부호가 없다. 상승·하락은 각각 최대 하나이고 서로 다른 능력치다.
  - 계산용 성격은 기준 가정의 성격에서 출발해 입력 부호를 만족하도록 맞춘다. 상승만 있으면 하락은 핵심 능력치가 아니고 H도 아닌 능력치에 둔다. 하락만 있을 때도 같은 방식이다. 둘 다 없으면 핵심 능력치에 보정이 없는 성격이다.
  - 패널 관측 줄은 보정이 붙어 있어도 그 부호 그대로 추가할 수 있다. 화면에 이미 있는 줄만 "이미 존재합니다"로 비활성이다.
  - 패널과 카드 '직접 추가'는 같은 ▲▼ 입력 부품과 같은 부호 규칙을 쓴다.
- **카드 조작 확장.** 카드 배분 메뉴의 추가·고정·삭제 조작은 출처와 상관없이 핵심 능력치가 있으면 보인다. 목록 밖 추가 배분도 같은 자리에서 지운다(R6).
- **의도로 남기는 동작.** 프리셋 1 편집으로 목록 밖 추가 배분이 다른 프리셋과 같은 키가 되면 그 추가 카드·배지는 숨는다. 이때 선택은 기본 선택지로 돌아간다(기존 래더 "가려진 추가 배분"과 같은 규칙).

### 결정 2. '포켓몬 추가' 패널 배치: 한 줄 스텝(시안 대안 A, 사용자 선택 2026-11-18). 검색 → 선택한 포켓몬 칩 → 모드 본문을 위에서 아래로 한 열에 둔다

- **형태: 앵커 팝오버** (빌드 중 개정 2026-11-18, 사용자 확인).
  - '포켓몬 추가' 버튼에 붙어 뜨는 팝오버다. 뒤 화면을 밀어내지 않고 위에 겹친다. 뒤 화면 조작은 막지 않는다(비모달).
  - 폭은 약 360px로 고정하고, 내용은 그 폭 안에서 줄바꿈한다. 화면 끝에 닿으면 화면 안으로 들어오게 위치를 맞춘다.
  - 좁은 화면(폭 약 480px 이하)에서는 화면 아래에 붙는 하단 시트로 뜬다.
  - 열면 팝오버 안으로 포커스가 들어간다. Esc·취소·바깥 클릭으로 닫히고, 추가 없이 닫으면 포커스가 버튼으로 돌아간다. 추가에 성공하면 닫히고 새 배분으로 포커스가 간다(R8).
- **1단계 검색.**
  - 검색창 하나로 로스터 전체를 찾는다.
  - 후보마다 상태 태그("메타 목록" / "표시 범위 밖" / "추가됨")를 붙이고, 태그 없는 후보는 새 목록 밖 포켓몬이다.
  - 한 번에 보이는 후보 수는 지금처럼 제한한다.
- **2단계 선택 칩.**
  - 포켓몬을 고르면 검색창 자리에 선택 칩(이름·상태 태그·"다시 검색")이 들어선다.
  - 탭을 바꿔도 칩은 유지되고, 본문만 새 탭 기준으로 다시 그린다(R10). 지금은 패널이 탭마다 따로 그려져 탭 전환 때 고른 포켓몬이 초기화된다. 그래서 패널 열림과 고른 포켓몬은 탭 전환에도 살아남는 앱 계층 상태로 둔다(열림 여부는 이미 앱 계층에 있다).
- **모드 본문(칩 아래).**
  - **새 목록 밖 포켓몬:** 기술 칩 1~4개를 고른다(지금 흐름).
  - **이미 있는 포켓몬, 스피드 탭:** 관측 배분 목록과 직접 입력을 둔다.
    - 관측 배분 목록은 점유율 기준 이상의 배분을 점유율과 함께 보이고, 줄마다 "+ 추가"를 둔다. 화면에 있는 줄은 "이미 존재합니다"로 비활성이다.

- **패널 안 관측 배분 목록 길이(PRD 열린 질문).** 화면 표시와 같은 점유율 기준 이상만 보인다. 기준 미달 배분은 직접 입력으로 더한다.
- **기존 진입점의 입력.** 스피드 배지 상세 "다른 배분 추가"는 패널 직접 입력과 같은 S SP·▲▼ 부품을 쓴다. 카드 메뉴 '직접 추가'는 같은 SP 검증·문구를 쓴다.

### 결정 3. 스피드 배지 상세: 앵커 팝오버로 띄운다. 그 줄 아래 인라인 펼침은 없앤다 (빌드 중 개정 2026-11-18, 사용자 확인)

  - 한 번에 하나만 열린다.

- 차트 프레임이 스크롤되면 팝오버가 배지를 따라간다. 배지가 화면 밖으로 나가면 닫는다.

## 선택지

결정 1(데이터 모델·판정 경계):

### 선택지 A: 최소 확장(상태 타입 변경 없음, 상대 id 의미만 넓힘)

- 장점: 상태 타입·액션이 그대로라 리듀서와 기존 상태 테스트가 거의 안 바뀐다. 범위 밖을 상태에 두지 않아 동기화가 필요 없다.
- 단점: 상대 id 하나가 메타 id와 목록 밖 id를 겸한다. 메타 월·매치 방식을 바꿔 목록 밖 종이 메타에 들어오면, 그 추가 배분이 조용히 메타 추가 배분으로 바뀌고 범위 밖 노출까지 일으킨다. 카드 id·고정 비교도 결국 출처 인자가 필요하다. 판정을 비동기 계획 카드에서 해서 계산 중에는 직전 계획 기준이 된다. 목록 밖 추가 배분의 고정·삭제 조작을 다루지 않는다.

### 선택지 B: 통합 모델(추가 배분 단일 컬렉션 + 단일 키 + 판정기 하나)

- 장점: 동일성 키 하나가 리듀서·씨앗·배지·카드 id·고정에 두루 쓰여 구조가 가장 깔끔하다. 탭이 늘어나도 확장하기 쉽다.
- 단점: 상태 필드 2개·액션 4개·타입 2개를 한 번에 없애는 리팩터다. 상태·계획·스피드 차트·수용 테스트 픽스처 대부분을 고쳐야 한다. 계산 세대 올림을 탭마다 갈라야 해서, 스피드 배분만 바꿨는데 공·방 실행기가 다시 도는 회귀 위험이 새로 생긴다. 되돌리기가 가장 비싸다.

### 선택지 C: 파생 질의(출처 판별자 + 범위 밖 파생 + 순수 판정 모듈) — 채택

- 장점: 상태 변경이 필수 판별자 하나와 목록 밖 삭제 연쇄뿐이다. 판별자가 메타 전환 때 id 공간이 겹치는 문제를 구조로 막는다. 범위 밖 노출이 파생이라 "모두 지우면 사라짐·다른 탭 무영향·설정 불변"이 정리 코드 없이 성립한다. 판정이 화면 표시와 같은 씨앗 함수를 쓰므로 R4의 "화면에 있는 것만"이 표시 기준과 자동으로 맞는다. 동기·순수 판정이라 단위 테스트로 잠근다.
- 단점: 탭 계획 안의 분류·씨앗 산출을 상대 단위 공개 함수로 뽑아야 해서, 공·방 계획 경로에 손이 간다. 추가 배분 타입 세 개에 필수 필드가 생겨 테스트 리터럴을 기계적으로 고쳐야 한다. 질의 함수를 결과·스피드 화면까지 내려 주는 전달 경로가 하나 는다.

## 결과

### 긍정적 영향

- 어떤 포켓몬이든 한 곳에서 새 배분을 더할 수 있다. 세 진입점이 같은 판정·문구를 쓴다.
- 중복 판정이 화면 표시 규칙과 같은 함수에서 나와, "보이는데 추가됨"이나 "안 보이는데 막힘"이 구조적으로 생기지 않는다.
- 목록 밖·범위 밖 포켓몬의 추가 배분이 메타 전환에도 출처를 잃지 않는다.
- 흩어진 유효성·동일성 검사가 한 곳으로 모인다.

### 부정적 영향 / 트레이드오프

- 동작이 바뀐다.
  - 범위 안에서 추가한 배분이 상위 N 축소나 선택 필터 뒤에도 "추가분만"으로 남는다. 기존 e2e AC26 단언을 갱신한다.
  - 카드 '직접 추가'에서 같은 배분이면 기존 선택지로 옮겨 가던 동작이 "이미 존재합니다" 안내로 바뀐다.
- 추가 배분 타입 세 개에 필수 출처가 생긴다. 상태·계획·스피드 차트·수용 테스트 리터럴을 고친다.
- 스피드 추가 판정의 "표시 중 래더 상대만" 방어가 사라진다. 대상이 맞는지는 질의 모듈과 패널 후보가 보장한다. 해당 단위 테스트 단언을 바꾼다.
- 탭 계획의 분류·씨앗 산출 추출로 공·방 계획 경로에 손이 간다. 알림 수집·도구 제거 순서가 바뀌지 않음을 기존 계획·수용 테스트로 증명해야 한다.
- 범위 밖 상대는 기준 가정을 얻으려고 관측 씨앗을 계산한 뒤 버린다. 계산 낭비가 조금 생긴다.
