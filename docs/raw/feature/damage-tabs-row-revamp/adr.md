# ADR: 공격·방어 탭 판정 행 기능 확장과 상세 화면 가시성 개편(상대 기술 표시·설정, 화력 도구 행)

> 범위: 이 ADR은 1단계(판정 행 기술 선택)의 구조 결정이다. 2단계(상세 가시성·화력 도구 행)는 PRD 개정 때 결정을 추가한다.
> 상위 ADR `../sp-sweep-table/adr.md`의 결정 2(카드 모델)를 부분 대체하고, 결정 1(카드 구성)·결정 3(계산 전략)의 해당 조항을 개정한다. 개정하지 않은 조항은 그대로 유효하다.

## 컨텍스트

- **PRD 요구**
  - 행의 기술 배지에서 기술(랭크업 포함)을 항목 목록으로 고른다(R1·R2·R3).
  - 고르기 전 기본 항목은 랭크 전·후 변동 비교와 방어 탭 선공기 우선으로 정한다(R4).
  - 직접 고른 항목은 (탭, 상대 포켓몬) 단위로 기억하고, 분류가 다르면 배분이 전환된다(R5·R6).
  - 별도 랭크 행·선공기 행·외 k행은 없어지고, 표시 기준은 보이는 항목 하나다(R7).
  - 성능 예산과 선택 반응 ≤ 500ms를 지키고, 같은 입력에서 기본 항목이 깜박이지 않는다.
- **현재 코드 제약**(조사 2026-11-13, notes '맥락')
  - 카드 = 상대 × 배분 묶음 × 분류이고, 카드 안에 조건 묶음(기본 + 랭크 수단마다)이 있다.
  - 조건마다 계획 시점 단건 판정으로 "가장 센 기술"을 고르고, 고른 후보와 선공기 후보에만 양 끝·스윕·변형·극단·쌍 작업이 생긴다.
  - 다른 분류 기술은 행 없는 비교 전용 후보다.
  - 대표 행은 카드 안 전 행에서 경계가 가장 가까운 행이고, 변동 가능은 아무 행이나 변동이면 참이다.
  - 배분 선택은 결과 패널 국소 상태이고, 배분 고정은 계산 입력이 아닌 앱 상태다.
  - 래더 카드는 1·2단계 뒤에 보인다.
- **사용자 경험 제약**
  - 배분 메뉴와 같은 조작 문법을 쓴다.
  - 기본 항목은 "SP로 바뀔 여지가 있는 쪽"이다.
  - 직접 고른 것은 SP를 바꿔도 남는다.
- **검증 제약**
  - 기본값 규칙은 화면 없이 단위 테스트로 재현할 수 있어야 한다(R4 표 8줄 + 선공기 조건).
  - 성능은 상위 단위 측정 스크립트로 다시 잰다.

## 결정

### 결정 1. 판정 행 모델: 카드·조건 묶음은 계산 단위로 유지하고, 그 위에 "항목" 층을 얹어 카드당 보이는 항목 하나만 행으로 낸다

- 계산 단위는 지금처럼 카드(상대 × 배분 묶음 × 분류)와 조건 묶음이다.
- 항목 = (기술, 랭크 조건)은 "어느 조건 묶음의 어느 후보인가"로 대응한다.
- 항목 목록은 상대 포켓몬 단위로 모은다. 한 포켓몬의 물리·특수 카드에 있는 후보를 합치고, 다른 분류 후보도 그 분류 카드의 정식 후보로 둔다. 비교 전용 후보 개념은 없앤다.
- 카드가 화면에 내는 판정 행은 보이는 항목 하나의 행(방어 탭은 H·B/D 쌍 또는 극단 필터 고정 1줄)뿐이다.
  - "가장 센 기술만 행" 규칙은 "기본 항목을 정하는 입력"으로 내려간다.
  - "선공기 유지" 규칙은 방어 탭 선공기 우선 규칙으로 대체된다.
- 대표 행, 변동 가능, 계산결과순, 열매 카드 노출, 목록 밖 타겟 카드 노출은 모두 보이는 항목 기준으로 계산한다.
- 방어 탭 랭크 수단 주인은 상대만 둔다. 내 B·D 랭크업은 이 탭에서 수단이 아니다.
- 스피드 탭은 이 층을 쓰지 않고 지금 모델 그대로다.

### 결정 2. 계산 범위와 순서: 기본 항목을 "확정된 뒤에만" 보이고, 확정에 필요한 최소 집합만 선계산하며, 나머지 항목은 선택 시 우선 작업으로 지연 계산한다

- **1단계(단건 판정)는 모든 항목에 돈다.** 목록 배지와 정렬에 쓴다. 지금 후보 단건 판정에 랭크 조건 후보가 더해질 뿐이라 구조가 같다.
- **기본값 판정은 필요한 것만 계산한다.** R4 표의 성질상 P가 변동이면 Q와 무관하게 P이고(3·5줄), P가 고정 확정1타면 P다(6줄). 그래서 다음 순서로 계산한다.
  1. 기준 기술의 랭크 전 항목 P의 변동 판정(공격 탭: 양 끝 → 필요하면 변형 스윕, 방어 탭: 극단 필터 → 양 끝 → 변형)
  2. P가 "고정이고 확정1타가 아님" 또는 "무효·계산 불가"일 때만 랭크 후 항목 Q들의 변동 판정
  3. 방어 탭은 스피드 비교(단건 계산, 판정 엔진 불필요)가 참일 때만 선공기 후보의 변동 판정
- **조기 확정.** 양 끝 판정이 서로 다르면 그 항목은 즉시 "변동"으로 확정하고 변형 스윕을 기다리지 않는다.
- **표시 시점.** 래더 카드는 "기본 항목이 확정되고, 그 항목의 판정 행이 1·2단계를 마친 뒤" 보인다. 이전에는 카드의 1·2단계 완료 뒤였다. 확정 전 카드는 지금의 미표시·갱신 중 규칙을 따른다. 그래서 같은 입력에서 기본 항목이 바뀌지 않는다.
- **우선순위 층.** 기본값 확정 작업은 지금의 활성 탭 1·2단계 층에 넣는다. 사용자가 고른 미계산 항목의 작업은 최상위 층(활성 탭 기본값보다 앞)에 넣는다. 나머지 단계(스윕 상세·쌍 탐색 등)는 지금 순서를 유지한다.
- **배분별 기본값(R4-5).** 배분 목록의 다른 배분 배지도 그 배분의 기본 항목이 필요하므로, 각 배분 카드에 같은 최소 집합 규칙을 적용한다. 계산량은 "조건마다 가장 센 기술 전체 작업"이던 지금보다 같거나 적다. P가 변동이면 랭크 조건 작업이 생기지 않기 때문이다.
- **방어 탭 스피드 의존.** 기본값이 내 스피드에 의존한다. 판정 캐시 키(관여 능력치)에는 S를 넣지 않는다. 판정 자체는 S와 무관하기 때문이다. 대신 내 스피드 입력이 바뀌면 새 계획에서 방어 탭 기본값을 다시 정한다. 드래그 중에는 다시 정하지 않는 기존 원칙은 그대로이고, S 드래그는 방어 탭 행을 갱신 대기로 만들지 않는다.

### 결정 3. 선택 상태: 앱 상태의 "기술 선택" 맵 — (탭, 출처, 상대) → 항목 안정 키. 계산 입력이 아니며, 미계산 항목은 실행기에 수요(demand)로만 알린다

- **위치.** 배분 고정과 같은 앱 상태에 둔다. 열매 카드·배분 전환과 공유하고 단위 테스트로 검증하기 위해서다. 새로고침하면 초기화된다.
- **키.** (탭, 출처[래더|목록 밖], 상대 id) → 항목 안정 키 = (기술 id, 랭크 조건[없음 | 수단 주인·종류·수단 id])다. 배분 묶음·분류·카드 id를 포함하지 않으므로 배분이 바뀌어도 같은 선택이다.
- **계산 입력이 아니다.** 선택해도 세대를 올리지 않고 캐시를 비우지 않는다. 보이는 항목의 판정 행이 아직 없으면 실행기에 그 항목 작업을 최우선 수요로 등록한다(결정 2). 직접 추가 배분처럼 계산 입력으로 만들면 선택마다 전체 재계산이 일어나 선택 반응 예산을 못 지킨다.
- **보이는 항목 결정(뷰 단계).**
  - 선택이 있고 그 항목 분류가 보이는 배분 분류와 같으면 선택 항목을 보인다.
  - 분류가 다르면 그 배분의 기본 항목을 보이고, 선택은 그대로 둔다(R5).
  - 사용자가 다른 분류 항목을 고를 때는 같은 동작으로 배분 선택(결과 패널 국소 상태)을 그 분류 기본 배분으로 바꾼다(R6).
- **사라짐 판정.** 그 탭의 새 계획이 만들어진 직후에, 계획의 항목 목록에 선택 키가 없으면 선택을 지운다. 계산 중간의 일시 상태로는 지우지 않는다.
- **되돌리기.** 맵에서 그 키를 지운다.

### 결정 4. 화면 배치: 기술 배지 = 배분 메뉴와 같은 드롭다운 메뉴 버튼(대안 A, 사용자 선택 2026-11-13)

- 간단행 기술 배지와 펼친 상세의 판정 행 제목 기술 배지가 각각 버튼이다. 기술 칩 테두리 안 끝에 펼침 화살표가 있고(호버·펼침은 기술 타입 색을 진하게), 누르면 같은 기술 선택 드롭다운 메뉴가 열린다(배분 메뉴와 같은 조작·위치 규칙).
- 메뉴 항목 = [기술 라벨(랭크 부호)] … [현재 판정 배지]. 센 순으로 정렬하고, 계산 불가와 무효 항목은 구분선 아래 맨 뒤에 둔다. 지금 보이는 항목에는 체크 표시가 붙는다.
- 직접 고른 상태에서는 메뉴 맨 위에 "기본값으로 되돌리기(기본 항목 이름)"가 있다. 배지·항목에 "직접"·"기본"·"선공"·"분산" 표지는 붙이지 않는다(사용자 피드백 2026-11-13: 표지가 거추장스러움).
- 행 펼침 클릭 영역에서 배지 영역은 분리한다. 배지를 눌러도 카드는 펼쳐지거나 접히지 않는다.
- 400px에서는 메뉴 폭을 화면 폭에 맞추고 좌우 여백을 둔다. 아래 공간이 모자라면 위로 연다.
- 비교 provenance: `design-options.html`(대안 A·B·C).

### 결정 5. 방어 탭 상대 기술 후보: 사용률 5% · 나에게 1배 이상 기준 + 사용자 추가 기술은 계산 입력(빌드 중 개정, 사용자 결정 2026-11-13)

- 래더 상대 기본 후보는 `defenseMoveIds`가 내 세트를 받아 정한다: 변화기 제외 · 사용률 ≥ 5% · 나에게 배율 ≥ 1, 없으면 사용률 1위 하나(PRD R2). 상위 5개 고정은 폐기한다.
- 배율은 코어 순수 함수로 계산한다: `attackEffectiveness`(상대 대표 세트 특성의 타입 변화·기술 특례) × 내 특성 보정(무효 0, 반감 0.5, 상대 틀깨기 계열이면 1). 대미지 계산을 돌리지 않는 이유: 후보 수를 정하는 계획 단계는 판정 엔진 없이 끝나야 하고(결정 2 단계 구조), 배율만으로 결정적으로 재현된다.
- 사용자가 추가한 상대 기술(`addedMoves`: 방어 탭 × 상대 종 → 기술 id 목록, 메모리)은 **계산 입력**이다 — 추가·삭제는 세대를 올린다. 후보가 늘면 계획(카드 후보·작업)이 바뀌므로 결정 3의 "선택은 계산 입력이 아니다"와 달리 계획에 들어가야 한다. 추가 직후 그 기술의 랭크 전 항목을 직접 선택(결정 3의 선택 맵)한다.
- 내 세트의 SP·성격 외 항목이 바뀌면 직접 선택 맵을 비운다(리듀서 `set-draft`에서 비교). 선택 키는 그대로 (탭, 출처, 상대)다.
- 검색 대상은 스냅샷 `species.learnset`(챔피언스 규정 데이터, 메가는 원종 습득표)에서 변화기·현재 후보를 뺀 것이며 기존 `learnableMoves`·`searchIndexOf`·`Combobox`를 재사용한다.

## 선택지

### 결정 1 (행 모델)

#### 선택지 A: 카드·조건 묶음 유지 + 항목 층 (채택)

- 장점
  - 묶음 키·캐시 키·실행기·배분 목록·고정 등 기존 계산 계층을 그대로 쓴다.
  - 바뀌는 곳이 "후보 → 행"의 노출 규칙과 표시 기준으로 국한된다.
  - 스피드 탭과 공존한다.
- 단점
  - 항목 목록을 포켓몬 단위로 모으는 층이 하나 늘어난다.
  - 다른 분류 후보가 정식 후보가 되면서 분류 카드마다 1단계 작업이 조금 는다(지금도 비교 전용 단건 판정은 돌고 있어 증가는 작다).

#### 선택지 B: 카드 안 행을 항목 단위로 재구성(조건 묶음 폐지)

- 장점: 모델이 개념(항목)과 1:1이다.
- 단점
  - 조건 묶음은 랭크 적용·반응·하양허브 처리의 단위라서, 폐지하면 랭크 계산을 항목마다 다시 짜야 한다.
  - 계획·실행기·테스트의 변경 폭이 크다.

#### 선택지 C: 카드를 상대 포켓몬 단위로 합치고 분류를 항목 속성으로

- 장점: "분류 전환"이 사라지고 배분 목록이 하나다.
- 단점
  - 묶음 키가 분류별로 다른 능력치(H·B 대 H·D)라 한 카드에 담을 수 없다.
  - 배분 목록·고정 키·성능 측정 기준이 모두 바뀐다.
  - 상위 결정의 카드 계약을 통째로 대체한다.

### 결정 2 (계산)

#### 선택지 A: 기본값 확정 후 표시 + 최소 집합 + 지연 계산 (채택)

- 장점
  - 깜박임 금지(PRD)를 구조로 보장한다.
  - P 우선 단락으로 대부분의 카드에서 랭크 조건 작업을 생략한다.
  - 미선택 항목은 비용이 없다.
- 단점
  - 공격 탭에서 양 끝이 같은 P는 변형 스윕까지 기다려야 표시된다. 첫 카드 시간이 늘 수 있어 측정으로 확인해야 한다.

#### 선택지 B: 단건 판정으로 잠정 기본값 표시 후 확정 시 교체

- 장점: 첫 카드가 가장 빠르다.
- 단점: 확정 시 기본 항목이 바뀌는 깜박임이 생겨 PRD 비기능·AC22를 정면으로 어긴다.

#### 선택지 C: 양 끝(방어는 극단)만으로 변동 근사

- 장점: 계산이 가장 싸고 빠르다.
- 단점
  - 성격 상승 변형 범위의 경계를 놓쳐 상위 "변동" 정의와 다른 결과를 낸다.
  - 카드의 "변동 가능" 표시와 기본값 근거가 어긋난다.

### 결정 3 (선택 상태)

#### 선택지 A: 앱 상태 맵, 계산 입력 아님, 수요 등록 (채택)

- 장점
  - 세대·캐시를 건드리지 않아 선택 반응이 빠르다.
  - 배분 무관 키라 R5 유지 규칙이 단순하다.
  - 단위 테스트가 쉽다.
- 단점
  - 실행기에 "수요" 경로가 새로 생긴다.
  - 사라짐 정리를 계획 생성 직후에 해야 한다.

#### 선택지 B: 계산 입력(직접 추가 배분처럼 세대 증가)

- 장점: 기존 입력 경로를 재사용한다.
- 단점
  - 선택마다 세 탭 전체가 재계획·재계산되어 선택 반응 예산과 깜박임 규칙에 불리하다.
  - 의미상 "보기 선택"을 계산 입력으로 취급하게 된다.

#### 선택지 C: 결과 패널 국소 상태(배분 선택처럼)

- 장점: 변경 범위가 화면 쪽에 국한된다.
- 단점
  - 실행기 수요·열매 카드 공유·분류 전환 연동이 화면 컴포넌트에 흩어진다.
  - 순수 함수 테스트가 어렵다.

### 결정 4 (화면 배치)

- 대안 A·B·C의 정보 우선순위·어포던스·트레이드오프는 `design-options.html` 각 카드 설명란에 있다.

## 선택 근거

- **결정 1**
  - "보이는 행만 바꾸고 계산 계층은 둔다"가 PRD 요구(행 표시·선택)를 가장 좁은 변경으로 만족한다.
  - B는 랭크 처리 단위를 깨서 기각했다.
  - C는 묶음 키가 분류별 능력치라는 상위 계약과 충돌해서 기각했다. 분류 전환은 R6의 "그 분류 기본 배분으로 전환"으로 충분하다.
- **결정 2**
  - PRD가 깜박임 금지를 요구하므로 B는 불가하다.
  - C는 "변동"의 정의를 바꿔 기본값 근거가 화면 표시와 어긋나서 기각했다.
  - A의 첫 카드 지연 위험은 두 가지로 줄인다. 하나는 R4 표의 P 우선 단락과 양 끝 조기 확정이고, 다른 하나는 "기본값 확정 작업"을 활성 탭 1·2단계 층에 두는 것이다. 측정에서 예산을 넘으면 기본값 확정 전 카드를 "갱신 중" 행으로 먼저 보이는 방식(깜박임 없음)으로 조정한다.
- **결정 3**
  - 선택은 "무엇을 보여 줄지"이지 계산 조건이 아니다. 배분 고정이 계산 입력이 아닌 것과 같은 성격이라 A를 택했다.
  - B는 선택 반응 예산을 해쳐서 기각했다.
  - C는 실행기와의 연결·공유 요구 때문에 화면에 로직이 쌓여서 기각했다.
- **결정 4** — 사용자가 대안 A를 수정 요구 없이 선택했다(2026-11-13).
  - A는 배분 메뉴와 같은 문법이라 학습 비용이 없다.
  - C는 배분과 기술을 동시에 보지 못하고, 분류 전환이 숨은 탭에서 일어나 인지하기 어려워 기각했다.
  - 2단계(상세 가시성 개편) 전에 상세 레이아웃을 늘리거나 바꾸지 않아, 2단계 결정의 여지를 남긴다.
  - B의 칩 줄은 2단계 상세 개편과 함께 다시 검토할 가치가 있다.

## 결과

### 긍정적 영향

- 사용자가 모든 후보 기술(랭크 포함)을 보고 고를 수 있고, 기본 항목이 "SP로 의미가 있는 쪽"을 보인다.
- 상세가 랭크 행·선공기 행만큼 짧아진다.
- 기본값 판정이 P 우선 단락으로 계산량을 늘리지 않는다.
- 선택은 세대를 올리지 않아 즉시 반응한다.

### 부정적 영향 / 트레이드오프

- 공격 탭 래더 카드는 기본 항목 확정(경우에 따라 변형 스윕)까지 늦게 보일 수 있다. 성능 재측정이 필수다.
- 방어 탭의 내 B·D 랭크업 행이 사라진다(후속 별도 UI까지 기능 공백).
- 다음 테스트와 계약을 대체한다.
  - 대표 행, 변동 가능, 외 k행, 열매 노출, 선공기 유지, 랭크 행 관련 단위·e2e 테스트
  - data-* 계약(`data-headline`·`data-variable`·`data-condition` 의미)

  바꾼 테스트는 notes에 PRD R7 "이전:" 항목과 매핑한다(AC24).
- 불변식 `INV-261113-rank-active-means-only`의 "탭별 수단 주인" 부분(방어 탭에서 내 B·D 제외)이 바뀐다. 이 ADR을 출처에 추가해 재판정한다.
