# PRD: 메타 사용률·상대 SP 분포 데이터 수집

## 배경

다음 단위의 제품 화면(SP 구간 판정 표)은 내 포켓몬 하나를 설정하면, 공격·방어·스피드 탭마다 주요 메타
포켓몬과의 계산 결과를 카드로 나열한다. 카드는 사용률 순으로 정렬하고, 상위 N마리만 보거나 원하는 포켓몬만
고를 수 있어야 한다. 카드 하나를 계산하려면 상대의 도구·특성·성격·SP 배분을 가정해야 하고, 스피드 탭은 상대가
얼마나 빠른지의 분포까지 필요하다. 지금 앱에는 이 가정을 만들 메타 데이터가 없어서, 계산 코어가 있어도 카드에
결과를 띄울 수 없다.

조사(notes.md "조사 결과: 통계 원천 실측") 결과는 다음과 같다.

- Smogon이 공개하는 Showdown 래더 월별 통계는 레귤레이션별·매치 방식(Bo1/Bo3)별로 나뉜 더블(VGC) 통계다.
  사용률과 종별 도구·특성·기술·동료 분포를 담고, SP 배분을 챔피언스 SP 단위 그대로 담는다. 같은 달에
  레귤레이션이 바뀌면 레귤레이션마다 따로 나온다.
- 레이팅 컷 0/1500/1630/1760 가운데 1760이 가장 상위 유저 쪽으로 가중된 통계다. 컷은 하드 필터가 아니라
  플레이어 레이팅이 컷을 넘을 확률로 가중하는 방식이다. 1760 컷의 실효 표본은 월 약 6천 배틀로 추정되며
  Bo1과 Bo3가 비슷하다.
- 이 통계는 브라우저에서 직접 받을 수 없어서 미리 받아 앱에 넣어야 한다. 원본은 최대 15MB(Bo1)라 그대로
  배포할 수 없다.
- 인기 포켓몬 중에도 SP 배분이 넓게 흩어진 종이 있다(예: 고릴타는 1위 배분이 4.9%이고 80%를 덮는 데 239개).
  잘라낸 배분만으로는 스피드 분포가 왜곡된다.
- 인게임 랭크 통계 사이트는 약관이 경합 서비스의 데이터 취득을 금지하므로 원천으로 쓰지 않는다.

사용자는 상위권 래더 통계라면 상대 가정으로 그대로 써도 된다고 판단했고, 갱신 단위는 원천의 달력 월로 정했다
(notes.md "결정" 2차). 나중에는 포켓몬별로 "이 SP 배분을 겨냥하고 싶다"는 커스텀 배분과, 참가자 SNS·구축
기사에서 모은 SP와 그 의도를 함께 쓰려 한다. 이 단위에서 그 확장을 막지 않는 데이터 구조를 먼저 잡는다.

## 목표

- [ ] 레귤레이션·매치 방식·월마다 상위권 래더 메타 통계 스냅샷을 만들고 보존해서, 앱이 레귤레이션을 지정하면
      그 레귤레이션의 메타 포켓몬 목록과 사용률 순위를 얻을 수 있다.
- [ ] 메타 포켓몬마다 계산 코어에 바로 넣을 수 있는 대표 상대 세트와, 스피드·내구 판단에 쓸 성격·SP 분포를
      얻을 수 있다. 대표 세트와 분포는 다음 단위의 카드 화면이 추가 가공 없이 쓴다. 근사 배분 묶기는 다음 단위의 몫이다.
- [ ] 상대 가정의 출처(래더 통계, 사용자 커스텀, SNS, 구축 기사)를 구분해 담을 수 있는 구조를 갖춘다. 이 단위에서
      채우는 것은 래더 통계뿐이다.

## 비목표

- 카드 리스트·탭·필터 같은 제품 화면. 다음 단위 `feature/sp-sweep-table`에서 한다. 이 단위의 확인 수단은
  테스트와 생성 리포트, 필요하면 기존 개발용 확인 페이지다.
- 메타 목록 밖 포켓몬(사용률 최소값 미만이거나 통계에 없는 포켓몬)의 가정. 이 포켓몬들에는 통계도 자동 기본값도
  넣지 않고, 사용자 커스텀 출처 가정으로만 다룬다(사용자 결정). 이 단위는 "래더 가정이 없음"을 구분해 알 수 있게
  하고 커스텀 출처 가정이 들어갈 구조만 연다. 사용자가 그 포켓몬을 타겟으로 고를 때 초기값 프리셋(해당 능력치 SP 32 /
  SP 32 + 성격 보정 / 무투자)을 채워 주는 것은 다음 단위 화면에서 한다.
- 사용자 커스텀 SP 배분의 입력·편집 기능, SNS·구축 기사 SP와 의도의 수집. 구조만 열어 둔다.
- 팀 단위 조합 집계와 대회 파티(Limitless 등) 수집. 기능 3 단위에서 한다. 종별 상위 동료(원천 값 그대로)는 포함한다.
- 통계의 주기적 자동 수집(CI 스케줄). 이 단위에서는 개발자가 명령으로 생성해 커밋한다.
- 인게임 랭크 통계, Pikalytics 등 다른 원천의 수집·교차 보정.
- 근사 중복 SP 배분(성격만 다르거나 자투리 SP 위치만 다른 배분)의 군집화. 원본 배분과 점유율을 그대로 보존한다.
- 시즌 단위 집계. 갱신 단위는 원천이 제공하는 달력 월이다(사용자 결정).
- 레이팅 컷 1760 외의 컷 보관. 싱글(BSS) 통계.

## 요구사항

### 기능 요구사항

- [ ] **스냅샷 단위**: 메타 통계 스냅샷은 (레귤레이션, 매치 방식 Bo1/Bo3, 달력 월)마다 하나다. 대상은 더블(VGC)
      통계이고 레이팅 컷은 1760이다. 같은 달에 레귤레이션이 둘이면 두 스냅샷이 나온다.
- [ ] **레귤레이션 대응 설정**: 레귤레이션과 원천 포맷의 대응은 설정으로 둔다. 새 레귤레이션이나 새 포맷은 설정만
      추가해 생성할 수 있고 코드를 고칠 필요가 없다.
- [ ] **선택**: 레귤레이션을 지정하면 그 레귤레이션의 사용 가능한 (매치 방식, 월) 목록과 기본 스냅샷을 얻는다.
      기본은 Bo1의 가장 최근 월이고(사용자 결정), 그 레귤레이션에 Bo1 스냅샷이 없으면 Bo3의 가장 최근 월이다. 지정한 조합이
      없으면 명확한 오류를 낸다.
- [ ] **메타 포켓몬 목록**: 스냅샷마다 포켓몬별 사용률과 사용률 순위를 제공한다. 순위는 사용률 내림차순이고, 동률이면
      식별자 순으로 정한다. 사용률이 최소값(조정 가능한 설정값) 미만인 포켓몬은 목록에서 뺀다.
- [ ] **목록 밖 판별**: 레귤레이션 로스터의 어떤 포켓몬이든, 그 스냅샷에 래더 가정이 있는지 없는지 구분해 알 수 있다.
      래더 가정이 없는 포켓몬에는 통계 값도 자동 기본값도 만들지 않는다. 그 포켓몬도 커스텀 출처 가정은 받을 수 있고,
      그 포켓몬의 가정은 커스텀 출처로만 생긴다.
- [ ] **메가 폼**: 원천이 메가 폼을 별도 포켓몬으로 집계하므로, 원천에 있는 메가 폼은 별도 항목으로 순위를 가진다.
      메가 판정과 연결은 원천 이름의 문자열 규칙이 아니라 게임 데이터 스냅샷의 폼 정보로 한다. 메가 항목은 기본 폼과
      해당 메가스톤을 함께 가리킨다.
- [ ] **세트 분포**: 포켓몬마다 도구·특성·기술·SP 배분(성격 포함)의 분포를 점유율과 함께 제공한다. SP 배분은 누적
      점유율이 목표(조정 가능)에 도달하거나 최대 개수(조정 가능)에 이를 때까지 점유율 순으로 보존하고, 보존한 배분이
      덮는 누적 점유율도 제공한다.
- [ ] **주변 분포**: 포켓몬마다 자르기 전 전체 배분에서 집계한 성격 분포와 능력치별 SP 분포(H·A·B·C·D·S 각각)를
      점유율과 함께 제공한다. 스피드에 영향을 주는 도구(예: 구애스카프)의 점유율은 도구 분포에서 그대로 얻는다.
- [ ] **대표 세트**: 포켓몬마다 가장 점유율이 높은 SP 배분을 대표로 바로 얻을 수 있다. 대표 세트는 그 배분과 최다
      도구·특성·기술 4개를 합친 것이며, 계산 코어의 세트 입력 검증을 통과해야 한다. 메가 항목의 대표 세트는 기본 폼 +
      해당 메가스톤 + 기본 폼 특성 + 메가진화 지정으로 구성한다. 원천의 메가 항목 특성 분포는 메가 폼 특성이므로,
      대표 세트의 기본 폼 특성은 ADR에서 정한 규칙으로 고르고 어떤 근거로 골랐는지 데이터에 표시한다. 메가 항목의
      최다 도구가 그 메가스톤이 아니거나, 메가 항목 특성이 메가 폼 특성 목록 밖이면 생성 리포트에 남긴다. 대표 세트는 최빈값 조합이라 실제 개체와 다를 수
      있음을 데이터에서 구분해 알 수 있다.
- [ ] **표본 지표**: 포켓몬마다 표본 규모 지표(1760 컷 가중 출현 수와 비가중 출현 수)를, 스냅샷마다 가중 배틀 수
      추정과 원천 배틀 수를 제공한다. 정확한 식은 ADR에서 정한다.
- [ ] **동료**: 포켓몬마다 상위 동료 포켓몬과 비율을 원천 값 그대로 제공한다.
- [ ] **이름 연결**: 원천의 포켓몬·도구·특성·기술 이름을 게임 데이터 스냅샷의 식별자에 연결하고, 한국어 이름을 얻을
      수 있다. 연결되지 않은 이름과 레귤레이션 규칙에 맞지 않는 값(로스터 밖 포켓몬, 사용 불가 도구, 그 포켓몬이 쓸 수
      없는 특성, 배울 수 없는 기술, 알 수 없는 성격, SP 범위·합계 위반 배분)은 생성 리포트에 종류별 개수와 빠진
      점유율을 남기고, 스냅샷 데이터에서는 제외한다. 제외한 뒤 남은 값의 점유율은 다시 정규화하지 않는다(원천 값과
      그대로 대조할 수 있게).
- [ ] **출처 구분**: 상대 세트 가정 하나하나에 출처 종류(래더 통계 / 사용자 커스텀 / SNS / 구축 기사), 출처 설명(통계면
      원천·매치 방식·월·컷, 그 밖이면 링크·작성자 등), 의도 텍스트(선택)를 담을 수 있다. 래더 통계가 아닌 출처의
      가정도 대표 세트와 같은 경로로 계산 코어에 들어간다. 이 단위의 스냅샷은 래더 통계 출처만 채운다.
- [ ] **생성 명령**: 개발자는 명령 하나로 지정한 (레귤레이션, 월)의 Bo1·Bo3 스냅샷을 만든다. 받은 원천 파일은 캐시하고
      원천의 해시를 설정에 기록한다. 캐시가 있으면 네트워크 없이 다시 만들고, 원천 해시가 기록과 다르면 실패한다.
- [ ] **결정론**: "같은 원천"은 같은 통계 원천 해시와 같은 게임 데이터 스냅샷 버전을 뜻한다. 같은 원천이면 생성물은
      바이트 단위로 같다. 메타 스냅샷은 연결에 쓴 게임 데이터 스냅샷의 식별자·버전을 기록한다. 생성 시각은 생성물에
      쓰지 않는다.
- [ ] **보존**: 지난 월 스냅샷은 덮어쓰지 않고 남는다. 이미 있는 스냅샷은 명시적 강제 옵션 없이 다시 만들지 않는다.
      게임 데이터 스냅샷이 갱신돼도 기존 메타 스냅샷은 그대로 두고, 재현성 검증은 현재 원천분에만 적용한다. 동결되지 않은 레귤레이션의 최신 월 메타 스냅샷은 현재 게임 데이터
      스냅샷과 일치해야 하며, 게임 데이터가 바뀌면 함께 다시 생성한다.
- [ ] **원천 검증**: 원천 형식이 예상과 다르면 생성이 실패하고 무엇이 달랐는지 알린다. 대상은 필수 필드 누락, 형식 정보
      불일치(포맷 이름이 설정과 다름, 컷이 1760이 아님), 레귤레이션과 맞지 않는 포맷, 원천 월이 레귤레이션 기간과
      겹치지 않음, 포켓몬별 분포 합이 서로 맞지 않음이다. 상성 정보(Checks and
      Counters)는 1760 컷에서 비어 있을 수 있어 필수 필드가 아니다.
- [ ] **출처 고지**: 앱에 포함하는 통계의 원천(Smogon University)과 원천 링크, 원천 월과 설정에 기록한 원천 공개
      시각을 기존 라이선스·출처 고지에 추가한다.

### 비기능 요구사항

- [ ] **배포 크기**: 스냅샷 하나(매치 방식 1개·월 1개)는 압축 전 1MB 이하다. 모바일 회선에서도 탭 전환 전에 받을 수
      있는 크기를 기준으로 했다. 앱은 지정한 스냅샷만 불러온다(모든 스냅샷을 한 번에 싣지 않는다).
- [ ] **로드 성능**: 개발 노트북 브라우저에서 스냅샷 데이터 수신 완료 시점부터 사용률 상위 30마리의 대표 세트를 얻을
      때까지(파싱 포함, 네트워크 제외) 20회 반복의 중앙값이 50ms 이하다. 같은 레귤레이션의 게임 데이터 스냅샷은
      이미 로드된 상태로 보고, 한국어 이름 조인과 계산 코어 세트 검증은 포함한다. 측정 환경·방법·캐시 상태를 기록한다.
- [ ] **결정론 확인**: 재생성해도 커밋된 생성물과 차이가 없다.
- [ ] **검증 가능성**: 실제 2026-10 M-C 원천의 일부를 동결한 테스트 입력으로 생성 결과를 검증한다(네트워크 없이 테스트가 돈다).
- [ ] **확장성**: 출처 종류가 늘어나거나 커스텀 배분이 추가돼도 기존 스냅샷과 그 소비 코드를 바꿀 필요가 없다.

## 수용 기준

- [ ] 2026-10 M-C의 Bo1·Bo3 스냅샷이 생성·커밋돼 있고, M-C를 지정하면 기본으로 Bo1 2026-10이 선택된다. 없는 (매치 방식,
      월)을 지정하면 오류가 난다. Bo1 스냅샷이 없는 레귤레이션을 테스트로 만들면 Bo3 최근 월이 기본이 된다.
- [ ] 생성한 M-C Bo1 2026-10 스냅샷의 사용률 상위 5마리와 사용률(소수 첫째 자리)이 원천 값과 같다. 조사 시점 원천 값은
      포푸니크 49.9%, 대도각참 42.2%, 대쓰여너 34.4%, 메가리자몽Y 32.3%, 고릴타 27.4%다(원천 사용률을 소수 첫째 자리로 반올림).
- [ ] 사용률 최소값 바로 아래인 포켓몬과 원천에 아예 없는 로스터 포켓몬은 목록에 없고, 조회하면 "래더 가정 없음"으로
      구분되며 래더 출처 가정·분포·사용률·자동 기본 세트가 함께 나오지 않는다. 그런 포켓몬에 커스텀 가정 하나를 주면 조회
      결과가 "래더 가정 없음 + 커스텀 가정 1개"이고, 그 가정이 계산 코어에서 결과를 낸다. 같은 사용률의
      포켓몬은 식별자 순으로 순위가 매겨진다(테스트 입력).
- [ ] 원천에 메가 폼과 기본 폼이 함께 있으면 별도 항목이다. 예를 들어 Bo1에서 한카리아스·메가한카리아스·메가한카리아스Z는
      별도 항목이다(리자몽은 Bo1 사용률 0.036%로 목록 밖이라, 리자몽과 메가리자몽Y의 별도 항목 여부는 최소값을 낮춘 테스트
      입력으로 확인한다). 메가리자몽Y는 기본 폼 리자몽과 메가스톤 리자몽나이트Y를 가리킨다. 메가한카리아스Z처럼 Z 메가도 해당 메가스톤과
      연결되고, 대표 세트가 계산 코어에서 메가 폼으로 해석된다.
- [ ] 포푸니크의 1위 SP 배분이 `고집 H2/A32/B0/C0/D0/S32`(점유율 13.2%, 소수 첫째 자리)로 나온다. 보존된 배분에 대해
      "누적 점유율 ≥ 목표"와 "보존 개수 = 최대 개수" 중 하나가 성립하고, 그 누적 점유율이 함께 나온다.
- [ ] 포푸니크의 S SP 32 점유율과 고집 성격 점유율이 원천 전체 배분에서 직접 집계한 값과 소수 첫째 자리까지 같다.
      고릴타처럼 배분이 넓게 흩어진 종에서도 주변 분포는 보존 개수 상한과 무관하게 전체 기준이다.
- [ ] 포푸니크의 최다 도구와 그 점유율, 최다 동료와 그 비율이 원천과 소수 첫째 자리까지 같다.
- [ ] 상위 5마리의 표본 지표가 ADR에서 정한 식대로 원천 값에서 나온다.
- [ ] 사용률 상위 30마리의 대표 세트가 모두 계산 코어 세트 검증을 통과한다. 그중 하나 이상(예: 대표 세트 대도각참의
      기습 → 대표 세트 포푸니크)이 실제 대미지 계산 결과를 낸다.
- [ ] 로스터 밖 포켓몬, 사용 불가 도구, 연결되지 않는 이름, SP 규칙 위반 배분을 섞은 테스트 원천으로 생성하면, 그 값들이
      스냅샷에서 빠지고 생성 리포트에 종류별 개수가 남는다.
- [ ] 필수 필드를 뺀 원천, 컷이 1760이 아닌 원천, 다른 레귤레이션 포맷의 원천으로 생성하면 실패하고 원인이 출력된다.
      상성 정보가 비어 있는 원천은 정상 생성된다.
- [ ] 캐시가 있는 상태에서 네트워크 없이 다시 생성하면 생성물이 바이트 단위로 같다. 캐시 원천을 1바이트 바꾸면 해시
      불일치로 실패한다. 이미 있는 스냅샷은 강제 옵션 없이 다시 만들어지지 않는다. 생성물에 연결한 게임 데이터
      스냅샷의 식별자·버전이 기록돼 있다.
- [ ] 설정에 테스트용 레귤레이션·포맷 대응을 추가하면 코드 변경 없이 그 스냅샷이 생성된다.
- [ ] 스냅샷 하나가 압축 전 1MB 이하이고, 로드부터 상위 30 대표 세트까지의 중앙값이 50ms 이하다(측정 기록 포함).
- [ ] 래더 통계가 아닌 출처(사용자 커스텀 배분 하나, 의도 텍스트 포함)의 가정을 테스트에서 같은 구조로 만들면, 대표
      세트와 같은 경로로 계산 코어에 들어가 결과를 낸다. 이때 기존 스냅샷 파일은 바뀌지 않는다.
- [ ] 라이선스·출처 고지에 Smogon 통계 출처·링크·원천 월·원천 공개 시각이 보인다.
- [ ] 대표 세트의 포켓몬(메가 폼 포함)·도구·특성·기술에 기존 한국어 매핑과 같은 한국어 이름이 붙어 나온다.

## 열린 질문

- (해결됨) 기본 매치 방식은 사용자가 Bo1로 정했다(카드에 나올 메타 포켓몬이 Bo3보다 많다). Bo3 스냅샷도 함께 보관한다.
- (해결됨) 메가 대표 세트의 기본 폼 특성 가정은 계산 결과에 영향이 없어 사용자가 그대로 받아들였다(메가진화 전 특성을
  타겟하는 경우는 드물다).
- (해결됨) 사용률 최소값은 0.5%다(ADR 결정 5). 그 미만은 목록 밖이며 커스텀 출처만 받는다(사용자 결정).
- SP 배분 보존은 누적 80% 또는 최대 30개로 정했다(ADR 결정 5). 다음 단위 화면을 보며 이 보존 기준만 조정할 수 있다.
- 1760 컷은 소수 고레이팅 유저에 강하게 가중돼 마이너 포켓몬의 분포는 노이즈가 크다. 표본이 작은 포켓몬을 표시할지·
  경고할지는 다음 단위 화면에서 정한다. 이 단위는 그 판단에 쓸 표본 지표를 담는다.
- Smogon 통계의 이용 조건은 공식 문구가 없다. 관례대로 출처를 표기하고 가공 결과만 넣는다.
- 다음 레귤레이션(M-D 추정, 2026-12-02 이후)의 포맷 이름은 아직 공지되지 않았다. 대응 설정으로 흡수한다.
- Showdown 래더 메타가 실제 인게임 랭크·대회 메타와 다를 수 있다. 커스텀·SNS·기사 출처 확장이 이 차이를 보완하는 수단이다.

## ADR 필요 여부

- **필요:** 이후 기능 1·2·3이 모두 의존하는 데이터 결정이 있다.
  1. 메타 통계 원천(Smogon chaos, 컷 1760)과 수집·캐시·해시 고정 방식, 원천 형식 검증 범위.
  2. 메타 스냅샷의 저장 구조와 키(레귤레이션 × 매치 방식 × 월), 기본 스냅샷 선택 규칙, 지연 로드 방식, 레귤레이션 대응
     설정, 기존 레귤레이션 게임 데이터 스냅샷과의 관계(버전 기록·동결).
  3. 상대 세트 가정의 데이터 계약: 출처 종류·출처 설명·의도 텍스트를 포함해 커스텀·SNS·기사 출처를 기존 데이터 변경 없이
     더할 수 있는 구조, 대표 세트(메가 포함) 구성 규칙.
  4. 원천 이름(메가 폼 별도 키 포함)을 게임 데이터 식별자로 연결하는 규칙과 규칙 위반 값의 처리.
  5. 보존 기준 기본값(사용률 최소값, SP 배분 누적 점유율 목표·최대 개수), 주변 분포·표본 지표의 정의, 배포 크기 근거.

  → `$adr-helper`로 넘어가 ADR을 쓰고, PRD와 ADR을 한 번에 사전 승인받는다. 화면이 없는 단위라 디자인 결정 레인은 쓰지 않는다.
