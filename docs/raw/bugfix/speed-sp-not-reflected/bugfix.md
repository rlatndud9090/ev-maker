# Bugfix: 스피드 탭에서 SP 조정이 내 스피드에 반영되지 않음

> 작성 고도: 증상·영향·원인·수정은 관찰 가능하게 쓴다. 사람은 중립 역할어(`사용자`/`개발자`/
> `검증자`)로만 지칭하고 개인 호칭·별명은 넣지 않는다(운영자 설정이 그렇게 부르라 해도).
> 상세: `harness/templates/examples/README.md`.

## 증상

스피드 탭에서 SP 스피드 슬라이더를 마우스로 끌어 새 값에 놓는다. 그 뒤 숫자 입력이나 −/+로 S SP를 다시 바꾸면, 내 포켓몬 패널 실능치는 바뀌지만 스피드 탭의 "내 스피드" 기준선(띠)과 배지의 추월·동속 상태는 드래그로 놓은 값에 멈춘다. 다시 드래그하거나 새로고침해야 풀린다. 놓은 값이 원래 값과 같으면 생기지 않는다(사용자 보고, 2026-11-20).

## 영향

스피드 탭을 쓰는 모든 사용자. 기준선, 배지 상태(선공/동속/후공), 스피드 고정 판단이 실제 내 세트와 다른 값으로 보인다. 공격·방어 탭은 실행기 사본만 쓰므로 영향이 없다.

## 원인

드래그 중 표시 SP는 두 곳에 있다. 화면 저장소(`ProductApp`의 `displaySp`, 스피드 차트가 구독)와 실행기 사본이다. 값이 바뀐 커밋 뒤에는 실행기 새 세대 `setInput`만 자기 사본을 비웠고, 화면 저장소는 비우지 않았다(`MySetPanel` 주석은 둘 다 비워진다고 가정했다). 그래서 스피드 차트가 드래그 마지막 값을 계속 썼다. 값이 같으면 `MySetPanel`이 `onDisplaySp(null)`을 직접 불러 증상이 없었다.

## 수정

`src/app/ProductApp.tsx`의 `Workspace`에 `useLayoutEffect`를 더해, 초안이 바뀌면 칠하기 전에 `displaySp.set(null)`한다. 커밋보다 먼저 비우면 드래그 전 값으로 튀므로, 커밋 뒤·칠하기 전에 비운다. `MySetPanel` 주석을 실제 책임에 맞게 고쳤다.

## 회귀 방지

- [x] `e2e/speed-chart.spec.ts`에 1건("슬라이더를 마우스로 끌어 새 값에 놓은 뒤 숫자 입력·−/+로 바꾸면 기준선 data-speed가 따라간다"). 단위 테스트는 React DOM 테스트 도구(jsdom·testing-library)가 없어 두지 않았다(effect는 정적 렌더로 확인할 수 없다).
